# project-export 模块（项目数据 Excel 导出）

| 字段 | 内容 |
|---|---|
| 类型 | 领域模块（只读聚合） |
| 职责 | 把一个项目的任务、日报 / 问题、变更、干系人导出为单个 xlsx；模板对齐现用企微智能表格导出的四张表 |
| 上游 | project / task / report-issue / stakeholder / file / identity（用户显示名）/ admin（审计） |
| HTTP | `GET /api/v1/projects/{id}/export?origin={站点 origin}` |
| 权限 | `project.export`（`RequirePermission` + `ProjectAccessGuard`；服务端仍按项目可见性裁决） |
| 审计 | 成功生成后写 `audit_logs`：`action=download`、`objectType=project`、`objectId/projectId=项目 id`，metadata 记格式、Sheet、行数与图片数 |

## 响应与文件名

- `Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`
- `Content-Disposition: attachment`，同时给 ASCII 回退名和 RFC 5987 的 `filename*=UTF-8''…`
- 文件名 = `[项目编号] 项目名称.xlsx`（编号 / 名称中的Windows 非法文件名字符、控制字符与末尾空格 / 点会被替换或清除；长度受控）
- `Cache-Control: no-store`、`X-Content-Type-Options: nosniff`
- 不生成 ZIP、JSON、封面、目录或进度弹窗；只生成一份工作簿

## 四个 Sheet（列序固定）

1. 首张 Sheet 名 = 项目名称（清洗后最多 31 字；与固定表名冲突时追加「项目」）
   - 18 列：任务描述 / 项目经理 / 任务负责人 / 任务状态 / 项目进度 / 是否按时交付 / 输出成果文件 / 项目进展描述 / 开始日期 / 预计完成日期 / 预计所需施工人数 / 预计所需天数 / 实际完成日期 / 阶段性里程 / 紧急重要度 / 结束时间 / 文件 / 变更关联
2. `日报及问题汇总`（11 列）：日期 / 填写者 / 当日完成工作 / 明日计划 / 现场工作附图 / 问题描述 / 问题归类 / 解决方案或建议 / 问题附图 / 问题是否处理 / 施工人数
3. `变更管理`（13 列）：变更时间 / 变更阶段 / 变更文件 / 变更内容描述 / 变更前 / 变更后 / 变更原因 / 变更申请人 / 填写者 / 变更后文件版本 / 变更后文件 / 进度 / 关联
4. `干系人`（7 列）：干系人姓名/name / 电话或whats app或微信号 / 邮箱Email / 职务Position/责任板块 / 所属公司company / 填写者 / 提交时间

前三张 Sheet 冻结首行首列（`B1`），干系人表不冻结。

## 字段口径

- 任务描述 = 中文标题 + 英文名（有则直接拼接，与样例一致）；状态 / 进度 / 按时交付取任务读面派生值。
- 任务「结束时间」= 该任务最近一次变更生效日期；「变更关联」按变更生效日期逐行展示。
- 任务日期 `M月D日`；日报日期 `YYYY年M月D日`（草稿追加「（草稿）」）；变更日期 `YYYY/M/D`；时间按 Asia/Shanghai。
- 日报按日期升序；问题按 `sourceReportId` 对齐到日报。同一日报多条问题用 `1 …` / `2 …` 编号；无来源日报的遗留问题另行成行，日期取提出时间。
- 变更「变更后文件版本」= 变更后文件名去掉最后一级扩展名（版本名沿用文件名，与样例一致），不是 `vN`。导入遗留变更没有文件时留空。
- 变更「变更内容描述 / 变更原因」从库内单列 `reason` 拆回两列（兼容应用内「；变更原因：」/「; Change reason:」与导入表「；原因：」；无法识别分隔符时整段作内容描述）。「变更阶段」= 系统九阶段显示名，样例中的历史自定义阶段名不反推映射。
- 干系人电话与微信合并为「电话 / 微信」；职务与责任板块合并并去重；公司 = 公司分类中文名 + 具体公司名（有则拼接）。
- 用户列展示「显示名(登录名)」；找不到账号时回退数据行里的姓名快照。
- 干系人字段不绕过字段级策略：复用 `StakeholderService.list(actorId)` 的读面输出，无联系方式 / 公司 / 职务权限时对应列按既有策略留空，不因导出权限额外放行。

## 文件列与图片

- 文件列只保留文件名 / 链接，不输出 fileId、对象键或二进制内容。
- 一个单元格有多份文件时逐行写文件名；Excel 单元格只能挂一个超链接，主链接指向第一份文件。
- 链接 = `{origin}/#/project/{projectId}?view=files`，打开项目详情的「项目文件」视图。`origin` 优先取前端显式回传的站点 origin（同源 GET 可能省略 `Origin`），其次 `Origin` / `Referer` / `X-Forwarded-Proto + Host`；只接受 http(s)，取不到时文件列只写文件名。
- 日报现场图 / 问题图、变更前后图直接嵌入单元格（PNG / JPEG / GIF，按文件头识别，不信任扩展名）；每个单元格内按列宽可容纳数量排成网格，图片横纵均留 4px 间距并通过 DrawingML 原生 EMU 锚点定位，超出首行自动换行；行高按图片行数扩展。
- 图片限制：最多 250 张、单张 8 MB、总计 80 MB、并发读取 4；缺失 / 读取失败 / 不支持的图片写「（附图缺失）文件名」，不阻断整份导出。

## 分页与边界

- 项目文件 / 任务 / 日报 / 问题 / 变更 / 干系人 / 用户目录按 200 条一页取满，最多 100 页（单类 20,000 条）；超出直接报 `INTERNAL` 提示分批导出，不静默截断。任务「文件」列复用一次取满的项目文件清单并按 taskId 分组，不逐任务查详情。
- 项目不存在、不可见或已被访问策略拒绝时，由 `ProjectAccessGuard` / 服务层返回 404 / 403；不额外暴露数据存在性。
