## 1. 目标与范围

### 1.1 目标

在企业微信智能机器人中，通过确定性命令查询某项目某一天的日报和问题：

- 单聊、群聊均支持。
- 支持项目编号、项目名称查询。
- 输出顺序固定为：文字与当天日报深链 → 日报海报/日报合集海报 → 问题海报/问题合集海报。
- 单篇已提交日报复用现有日报海报与问题专报视觉。
- 多篇已提交日报新增日报合集海报与问题合集海报。
- 图片失败不影响整次查询结果。

### 1.2 非目标

- 第一版不接大模型，不做自然语言自由问答。
- 不新增公开 HTTP API；查询入口仅为企业微信机器人回调。
- 不写业务审计、outbox、站内信或群播报记录。
- 不持久化用户查询历史、聊天正文或生成的海报字节。
- 群聊不开放跨项目查询。
- 不改现有群同步 `group-sync` 的业务行为和幂等语义。

## 2. 已确认前提

### 2.1 群聊发送人身份映射（P0 · 已完成）

此前已在测试环境验证：

1. 同一用户完成智能机器人单聊绑定；
2. 该用户在同一机器人的项目群发送消息；
3. 群回调 `from.userid` 与单聊绑定表 `wecom_aibot_dm_activations.wecom_userid` 完全一致。

结论：群聊可按 `(bot_id, from.userid)` 复用单聊绑定行映射到系统用户，群聊查询具备身份校验基础。

本结论只记录比较结果，不记录原始 `open_userid`、`chatid` 或任何聊天正文。S7 验收时随群聊回归再复验一次，但不作为 S1/S2 开工门。

### 2.2 已确认产品口径

- 单聊、群聊均要求发送人具备项目 `report.view`。
- 查询问题内容额外要求 `issue.view`。
- 无 `issue.view` 时仍返回日报部分，隐藏问题正文、问题数量和问题海报。
- 项目名称重名时只提示可用编号，不返回任何日报、问题或海报。
- 单聊图片采用方案 A：先被动回复文字，再主动上传并发送图片。
- 图片生成失败、超过 10MB、超过图片数量限制或发送失败时，回退为文字 + 链接，不能让整次查询失败。
- 单聊用户关闭主动提醒 `messagesEnabled=false` 不阻断其主动发起的查询回复。

## 3. 复用边界

### 3.1 可复用

- `server/src/modules/notify/daily-report.poster.ts` 的 `renderDailyReportPoster` 与 `renderDailyReportIssuePoster`。
- 现有 1440px 宽、深色页眉、黄/橙强调色、思源黑体、动态高度和附图排版。
- `sendGroupImage` 的群图片上传、限速、回执和错误分类能力。
- `wecom_groups` 项目群绑定关系与群会话激活态。
- `wecom_aibot_dm_activations` 单聊绑定与身份映射。
- `ObjectStorage` 按 `objectKey` 读取附图字节的方式。

### 3.2 不复用

`POST /projects/{id}/reports/{reportId}/group-sync` 及其 `syncToProjectGroup` 业务入口不复用：

- 仅项目经理可操作；
- 一次只同步一篇日报；
- 按日报版本去重；
- 写审计、outbox 和群播报记录；
- 是“主动通知”，不是“按人权限即时查询”。

查询必须新增只读链路，仅复用海报渲染、对象读取和图片发送能力。

## 4. 命令契约

### 4.1 语法

```text
查询 [项目] <项目编号或项目名称> [日期] [日报|问题|日报和问题]
```

解析规则：

- 单聊必须显式指定项目；群聊可省略，省略时使用群绑定项目。
- 缺省日期为今天；缺省主题为“日报和问题”。
- 项目编号取 `projects.code`，不是 `seqNo`。
- 项目名称采用归一化精确匹配：NFKC → trim → 合并连续空白 → 小写；不做模糊搜索。
- 项目名称含空格时必须加引号。
- 支持 `今天`、`昨天`、`前天`、`YYYY-MM-DD`、`YYYY/MM/DD`、`YYYY年M月D日`。
- 日期固定按 `Asia/Shanghai` 解释；未来日期拒绝。
- 解析前去除 `<@...>`、`@LibiaoLink` 和首尾空白。
- 消息以“查询”开头但语法错误时，返回命令帮助；不继续进入绑定码链路。

### 4.2 示例

群聊：

```text
@LibiaoLink 查询 昨天日报和问题
@LibiaoLink 查询 项目 PRJ-001 2026-11-10 日报和问题
@LibiaoLink 查询 项目 "临港数据中心" 昨天日报
@LibiaoLink 查询 昨天问题
```

单聊：

```text
查询 项目 PRJ-001 2026-11-10 日报和问题
查询 "临港数据中心" 昨天日报
查询 PRJ-001 前天问题
```

### 4.3 项目重名

单聊按项目名称查询时，如发送人可见范围内存在多个同名项目，只返回编号提示，不返回任何业务数据：

```text
项目名称「临港数据中心」匹配到 2 个可见项目，请使用编号查询：
1. PRJ-001（临港数据中心）
2. PRJ-008（临港数据中心）
```

规则：

- 只列出发送人可见的项目。
- 不返回日报、问题、深链或海报。
- 用户后续使用项目编号重新查询。

群聊由群绑定项目消除项目歧义：未显式指定项目时使用群绑定项目；显式指定的项目必须解析为群绑定项目，否则回复“本群仅支持查询已绑定项目”。

## 5. 回调查询路由

### 5.1 单聊

```text
单聊回调
  → 查询功能未启用：原 enter_chat / 绑定码 ingest
  → 查询功能启用且命中“查询”前缀：查询处理，结束
  → 未命中：原 enter_chat / 绑定码 ingest
```

查询命中时：

- 必须登记单聊会话激活，供图片发送时 `dmActivated` 分类使用；
- 不得增加绑定失败次数，不得触发绑定码防猜锁；
- 不得继续执行 `extractBindingCode`。

### 5.2 群聊

```text
群聊回调
  → 原群会话激活 / 候选群登记
  → 查询功能启用且命中“查询”前缀：查询处理
  → 未命中：原群名命令链路
```

群查询必须先完成会话激活，再读取群绑定项目和发送人身份。

### 5.3 命令优先级

`server/src/modules/notify/notify.dm.service.ts` 的 `extractBindingCode` 会从正文任意位置提取 6 位数字。查询识别必须先于绑定码提取，避免项目编号或日期中的数字被误识别为绑定码。

现有接线位置：`server/src/entry/worker.ts` 的 `aibot.onMessage` 回调分流。

## 6. 身份与权限

### 6.1 单聊

1. 按 `(bot_id, from.userid)` 查绑定行 `wecom_aibot_dm_activations`。
2. 未绑定、绑定用户不存在、已停用或已删除：回复绑定指引，不查询数据。
3. 解析项目并调用 `PermissionService.resolveProjectAccess(actorId, projectId)`。
4. 校验 `report.view`。
5. 查询包含问题内容时，额外校验 `issue.view`。
6. 查询数据并先回复文字，再发送海报。

### 6.2 群聊

1. 校验 `chatid`。
2. 按 `chatid` 查 `wecom_groups` 项目群绑定；未绑定群不输出日报数据。
3. 按 `(bot_id, from.userid)` 查单聊绑定行，得到系统用户。
4. 校验群绑定项目和发送人 `report.view`。
5. 显式项目必须等于群绑定项目；不能查询其他项目。
6. 查询包含问题内容时，额外校验 `issue.view`。

群聊只允许查询群绑定项目。发送人有权限不代表群内所有人都具备权限；限制到群绑定项目，可与现有日报群同步已经形成的暴露范围保持一致。

### 6.3 统一错误口径

- 项目不存在、项目不可见、无 `report.view`：统一回复“项目不存在或你无权查看”，不输出数据。
- 群未绑定：提示到“企微绑定”页绑定项目群，不输出数据。
- 群发送人未绑定：提示先完成单聊绑定，不输出数据。
- 群查询其他项目：回复“本群仅支持查询已绑定项目”，不透露其他项目信息。
- 无 `issue.view`：日报正常返回；问题正文、问题数量、问题链接和问题海报全部不输出。

## 7. 数据查询口径

### 7.1 新增读面

wmj 在 `report-issue` 模块新增只读 `ReportDigestService`，返回查询日快照：

- 项目 UUID、编号、名称。
- 已提交日报：`state` 为 `submitted` 或 `supplement`。
- 草稿数量；草稿正文、阶段和附图不返回，不进入海报。
- 日报按 `submittedAt`、`createdAt`、`id` 稳定排序。
- 同人同项目同日多篇日报逐篇返回。
- 每篇日报包含填写者、提交时间、状态、关联阶段、当日完成、明日计划、现场附图元数据。
- 问题按 `issues.raised_at = 查询日期` 查询。
- 问题返回当前状态、当前责任人、解决方案、来源日报、问题附图元数据；不还原历史状态。
- 附件按日报 ID / 问题 ID 批量读取，避免逐篇 N+1 查询。

新增 `IssueRepository.listByRaisedDate(projectId, date)`。`raised_at` 是 DateOnly，禁止用 UTC 时间窗重算日期。

### 7.2 问题口径

“当天问题”指项目内 `raised_at = 查询日期` 的全部问题，包含：

- 由当天日报自动生成的问题；
- 当天手工创建的问题；
- 由补填日报生成、提出日期为查询日的问题。

不能直接使用 `ReportSummaryService.issueCount`：该字段统计“现场发现问题非空的日报条数”，不是问题总数。

现有 `findDailyReportPosterData` 只查询 `sourceReportId = reportId` 的派生问题，不能直接作为按日查询的数据源，否则会漏掉手工问题。单篇可复用问题海报渲染器，但输入数据必须替换为查询日全量问题。

### 7.3 一致性

- 一次查询只生成一份数据快照。
- 文字、日报海报、问题海报全部使用同一快照，避免图片发送前再次查询导致数量或内容变化。
- 查询在 `repeatable read` + `read only` 事务内读取日报、问题和附件元数据。
- 只有进入海报渲染阶段才读取附件字节。

## 8. 文字输出与深链

### 8.1 输出顺序

1. 生成数据快照；
2. 生成文字；
3. 被动回复文字；
4. 文字送达后生成并发送日报图；
5. 再生成并发送问题图。

文字必须自包含，即使所有海报均失败，也能通过链接查看完整内容。

### 8.2 文字示例

```text
**项目日报查询 · 2026-11-10**
项目：临港数据中心（PRJ-001）
已提交日报 3 篇（其中补填 1 篇），草稿 1 篇；问题 2 条

[查看当天全部日报](https://pm.libiaorobot.com/#/project/{projectId}?view=daily&date=2026-11-10)
[查看当天问题](https://pm.libiaorobot.com/#/project/{projectId}?view=daily&sub=issues&date=2026-11-10)

1. 张三 · 09:12 · [打开该篇日报](...&report={reportId})
2. 李四 · 10:05 · [打开该篇日报](...)
```

规则：

- 项目、日期、数量和主深链优先保留。
- 单篇日报使用 `report={reportId}` 精确定位。
- 多篇日报使用新增的 `date=YYYY-MM-DD` 日期定位。
- 问题链接使用 `sub=issues&date=YYYY-MM-DD`。
- 无 `issue.view` 时不输出问题数量、问题链接和问题海报。
- 文字超过企业微信 markdown 字节上限时，先截断逐篇列表，不得截掉主深链。
- 项目名、姓名、用户内容进入 Markdown 前必须转义。
- 不使用对象存储直链。

### 8.3 前端日期深链

px 在 `frontend/src/useHashRoute.ts` 增加 `date` 参数，并让 `frontend/src/components/ReportIssuePanel.tsx` 的记录表与问题追踪按日期过滤：

```text
#/project/{projectId}?view=daily&date=YYYY-MM-DD
#/project/{projectId}?view=daily&sub=issues&date=YYYY-MM-DD
```

要求：

- 旧链接行为不变。
- 非法日期参数忽略并清理。
- 日期筛选可被用户清除。
- `report={reportId}` 精确定位行为保持不变。
- 同次提交更新 `前端功能需求.md`。

## 9. 海报策略

### 9.1 单篇与多篇

| 场景 | 日报图 | 问题图 |
|---|---|---|
| 1 篇已提交日报 | 复用 `renderDailyReportPoster` | 有问题且有 `issue.view` 时复用现有问题专报渲染器 |
| 2 篇及以上已提交日报 | 新增日报合集海报 | 有问题且有 `issue.view` 时新增问题合集海报 |
| 0 篇已提交日报 | 不发日报图，只发文字和深链 | 有问题且查询问题时可发问题合集 |
| 草稿 | 不进入任何海报 | 不进入任何海报 |

“单篇/多篇”按非草稿日报篇数判断，补填日报计入。

### 9.2 日报合集海报

建议新增 `renderDailyReportDigestPoster`：

- 页眉：项目编号、项目名称、日期、已提交篇数、草稿篇数。
- 每篇日报卡片：填写者、提交时间、补填标识、关联阶段、当日完成、明日计划。
- 每篇的现场附图限量展示。
- 长文本自动换行。
- 内容预算耗尽时显示“完整内容请点击上方深链”，不得无限增高。

### 9.3 问题合集海报

建议新增 `renderDailyReportIssueDigestPoster`：

- 页眉：项目编号、项目名称、日期、问题总数。
- 每条问题：描述、归类、当前状态、责任人、解决方案、来源日报。
- 每个问题限量展示附图。
- 长文本自动换行。
- 内容预算耗尽时显示“完整内容请点击上方深链”。

### 9.4 视觉与预算

- 沿用现有品牌视觉：1440px 宽、深色页眉、黄/橙强调色、思源黑体。
- 建议常量初值：画布最大高度 16000px；整张图最多 8 张附件缩略图；每篇日报最多 1 张图；每个问题最多 1 张图。
- 预算与具体视觉由 lan 实现、px 复核；调整后直接更新本文件。
- 渲染后必须检查 PNG 字节数，超过 `WECOM_AIBOT_IMAGE_MAX_BYTES`（10MB）则跳过该图。

## 10. 单聊图片发送（方案 A）

### 10.1 发送步骤

1. 使用 `replyToCallback` 被动回复文字，透传回调 `reqId`。
2. 使用现有 `uploadImage` 完成 `aibot_upload_media_init/chunk/finish`，取得 `media_id`。
3. 新增 `sendUserImage`，发送 `aibot_send_msg`：

```ts
{
  target: userid,
  chatType: 1,
  rateKind: "single",
  channel: "wecom_aibot",
  bucketId: userBucketId(userid),
  activated: dmActivated,
  message: {
    msgtype: "image",
    image: { media_id: upload.mediaId }
  }
}
```

其中帧字段 `chatid = from.userid`，即绑定行中的密文 `open_userid`；`chat_type = 1`。

### 10.2 必须修正项

`server/src/modules/notify/wecom.aibot.ts` 的 `uploadFailure` 当前固定按 `wecom_group` 分类。单聊上传命中 846607 时会分类错误。必须让上传方法接收 `channel` 和激活态：

- 群聊：`classifyWecomErrcode("wecom_group", ..., { groupActivated })`
- 单聊：`classifyWecomErrcode("wecom_aibot", ..., { dmActivated })`

`sendUserImage` 必须复用 `validateAibotImage` 的 PNG/JPEG/GIF、文件名、10MB 和分片数校验。

### 10.3 消息开关

`messagesEnabled` 表示是否接收主动单聊提醒，不是查询授权开关。用户主动发起的查询仍回复文字和图片。

## 11. 失败兜底、限流与幂等

### 11.1 图片兜底

每次查询最多发送 2 张逻辑图片。以下任一失败只跳过对应图片并记录日志：

- Canvas 渲染异常；
- 字体缺失；
- 附件解码失败；
- 图片超过 10MB；
- 文件名或分片数不合法；
- 上传失败；
- 发送失败；
- 本地限速拒绝；
- 海报并发闸门拒绝。

处理要求：

- 不回复“查询失败”；
- 不重发已送达文字；
- 日报图失败后仍尝试问题图；
- 文字和主深链已经自包含；
- 连续图片失败进入运维日志/告警，不向用户输出内部错误。

### 11.2 文字发送失败

- 被动回复在本地未就绪或本地限速拒绝时，可降级为主动 markdown 推送。
- 回执超时等“可能已送达”的失败不自动重发，避免重复消息。
- 文字完全未送达时不发送孤立的图片。

### 11.3 查询级限流

- 同一发送人单聊建议 5 秒内最多发起 1 次查询。
- 同一项目群建议 5 秒内最多处理 1 次查询。
- 海报全局同时最多渲染 1 张，排队最多 2 个任务；超出直接只发文字。
- 企业微信自身 30 条/分钟、1000 条/小时限制继续由现有 `WecomRateLimiter` 执行。

### 11.4 幂等

- 第一版以 `bot_id + msgid` 做 10 分钟、容量 1000 的内存 LRU 去重。
- 重复回调不重复回复。
- 多 worker / 多实例部署前必须升级为数据库幂等表。

## 14. 测试与验收矩阵

### 14.1 命令与路由

- 查询命令不会进入 `extractBindingCode`。
- 6 位数字项目编号、日期和正文数字不会计入绑定失败。
- 普通 6 位绑定码仍按原链路工作。
- `enter_chat` 欢迎语、群名命令、候选群登记无回归。
- 非法命令返回帮助，不回退到绑定码。

### 14.2 身份与权限

- 单聊未绑定不输出数据。
- 群聊发送人未绑定不输出数据。
- 绑定用户停用或删除不输出数据。
- 群未绑定不输出数据。
- 群只能查询绑定项目。
- 无 `report.view` 不输出日报。
- 无 `issue.view` 仍返回日报，但不输出问题内容、数量、链接和问题海报。
- 项目名称重名只返回编号；不可见项目不出现在提示中。
- 项目编号、项目名称、不可见项目和无权限项目使用统一错误口径。

### 14.3 数据

- 草稿只计数量，不进入文字列表和海报。
- 已提交与补填日报逐篇返回。
- 同人同项目同日多篇日报不合并、不丢失。
- 当天手工问题与日报派生问题都返回。
- 问题状态、责任人、解决方案使用当前值。
- 附图缺失、过期或单张读取失败不影响其余内容。
- 无日报、无问题、只有草稿、只有问题等空态正确。

### 14.4 文字与深链

- 文字先于图片发送。
- 单篇 `report` 深链精确定位。
- 多篇 `date` 深链精确过滤日报。
- 问题 `sub=issues&date` 深链精确过滤问题。
- 非法日期参数不影响旧链接。
- 文字超限时主深链仍在。
- Markdown 特殊字符已转义。

### 14.5 海报

- 单篇日报与现有群同步海报视觉一致。
- 单篇问题专报复用现有视觉且包含当天全量问题。
- 多篇日报生成一张日报合集海报。
- 多篇问题生成一张问题合集海报。
- 长文本、长项目名、多附件正确换行和排版。
- 0 问题不发送空问题海报。
- 图片超过 10MB 时不发送该图。
- 渲染异常、字体缺失、附件解码失败时文字仍完整送达。
- 海报高度与附件数量预算生效，不无限增高。

### 14.6 发送与故障

- 单聊 `sendUserImage` 帧为 `chatid=userid`、`chat_type=1`、`msgtype=image`、限速桶 `single`、渠道 `wecom_aibot`。
- 单聊上传 846607 按 `dmActivated` 正确分类。
- 群图片发送帧与现有 `sendGroupImage` 一致。
- 上传失败、发送失败、限速拒绝只跳过对应图片。
- 文字送达后不因图片失败重发文字。
- 重复 `msgid` 不重复回复。
- 查询冷却和海报并发闸门有效。
- worker 重启后不产生持久化脏数据。

### 14.7 安全与日志

- 日志不包含聊天正文、Secret、完整 `open_userid`、完整 `chatid`。
- 不输出对象存储直链。
- 无权限场景不泄露项目存在性。
- 不写业务审计、outbox 或站内信。
- 不将海报字节持久化到业务表或对象存储。

## 16. 风险

- 群聊数据面向整个群可见；必须保持“只查群绑定项目”的硬限制。
- `notify` 与 `report-issue` 若直接互相依赖，会破坏模块边界。
- 查询识别晚于绑定码提取会导致项目编号/日期误绑定。
- 现有问题海报快照只查来源日报问题，不能直接用于按日查询。
- 多篇 Canvas 海报可能阻塞 worker；必须并发闸门和内容预算。
- 缺少前端 `date` 深链会让多篇查询落到未筛选列表。
- 内存幂等只适用于单 worker；多实例前必须升级数据库幂等。
- 图片发送失败必须始终视为“降级”，不能升级为整次查询失败。
- 日志、审计和错误文案不得泄露正文、完整 open_userid、chatid 或对象存储细节。
