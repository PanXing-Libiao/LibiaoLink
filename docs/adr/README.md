# LibiaoLink 架构决策记录（ADR）索引

> ADR（Architecture Decision Record）记录「已经做出的架构决策」及其理由、备选与切换触发条件，是实现与升级的定档依据。与《技术设计》冲突时以 ADR 为准，并回写对应设计文档。
>
> - 归属：团队分工.md §4 —— ADR 由 wmj 主责，全员评审（lan / px 互为评审）。
> - 状态流转：草案（Proposed）→ 已采纳（Accepted，随 PR 合并 main）→ 被取代（Superseded，注明取代者）/ 作废（Deprecated）。
> - 本批来源：技术设计v0.1-选型分析.md §0.1 / §4 / §5 / §9 的选型结论固化（定档任务 g1 · S5·ADR）。
> - 后续来源：ADR-018 来自《技术设计v0.3-实施与验收.md》（实施与验收篇）；**ADR-019 ~ ADR-029 为 M0 口径冻结决议**（2026-09-20 · Push 71，来源 = 技术设计v0.3 §7 十五项待定案清单）；**ADR-030 来自 ONLYOFFICE 替换执行计划（PoC-10 · 2026-09-30）**；**ADR-033 来自 M5-03 单聊改智能机器人执行计划（企微单聊 · M5-03-5 · 2026-10-14）**；**ADR-034 来自安全审查 H1 与《H1 SVG 预览同源存储型 XSS 整改方案》（2026-10-20）**。

## 模板与编写规则

新增 ADR 使用以下模板（文件名：ADR-0NN-主题.md）：

~~~markdown
# ADR-0NN 标题（一个决策一句话）

- 状态：草案（Proposed）｜评审：lan、px｜随 PR 合并 main 后转「已采纳（Accepted）」
- 日期：YYYY-MM-DD｜决策人：（姓名）
- 依据：文档名 + 章节

## 背景

（要解决的问题、硬约束、量化依据。）

## 决策

（做成的决定；必要处给出不计较的边界与不变量。）

## 备选与不采用原因

（每个备选一句话说明为何不采用。）

## 影响与后果

（正面 / 负面 / 落地约束。）

## 切换触发条件

（什么情况出现时重新评估本决策。）

## 参考

（文档与章节。）
~~~

规则：

1. 一条 ADR 只记一个决策；编号不复用、不跳号，按顺序追加；
2. 决策变更不修改历史结论——新增 ADR，并在旧 ADR 标注「被 ADR-0NN 取代」；
3. 每条 ADR 必须写明：背景、决策、备选与不采用原因、影响与后果、切换触发条件、参考；
4. 与《技术设计》冲突或发现口径差异时，在 ADR 内以「待复核差异」显式记录，不静默选择（示例见 ADR-017）；
5. ADR 属高风险评审范围（架构与基础设施），合并前必须取得非作者评审（CONTRIBUTING.md §15）。
