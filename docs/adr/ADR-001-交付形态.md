## 背景

本项目的四个硬需求——图纸 / 三维在线预览、字段级权限与脱敏、自动化规则的复杂语义、与企微 / ERP 的深度集成——同时要求数据不出内网（不允许上传第三方云）。可选路线只有三类：低代码平台、成品项目管理系统、自研。

## 决策

**自研**（延续旧项目路线），在现有仓库上原地演进：不另起 monorepo、不做目录大搬迁。

## 备选与不采用原因

- 低代码平台（简道云 / 明道云 / 宜搭 / 氚云等）：复杂条件与回写语义受限；字段级权限多数只到视图 / 表单级；CAD / 三维预览基本没有；数据主权与合规不可控；按用户年订阅的长期成本持续累积。
- 成品项目管理系统：定制与集成受厂商边界限制；预览与权限能力弱；长期演进受厂商版本节奏约束。

## 影响与后果

- 正面：预览管道、权限策略、自动化语义、集成层全部可控；数据完全自主；演进不受第三方边界限制。
- 负面：开发人力与运维责任由团队承担（2 后端 + 1 前端 / 运维，见团队分工.md）；因此一期主动裁剪范围——甘特图、移动端专项、ERP 实现移出一期。
- 落地约束：实现必须遵循本目录 ADR 与技术设计口径；重大偏离需新增 ADR。

## 切换触发条件

公司战略要求 3 个月内上线且允许数据在第三方时，可先用低代码承接日报与问题闭环作为过渡，**核心数据底座仍自研**。
