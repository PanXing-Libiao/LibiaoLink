# ADR-033 企微消息通道改由智能机器人（aibot）承接（群播报 + 单聊 · 应用消息保留备用）

## 背景

一期消息通道原口径（ADR-009）：企微自建应用消息（个人提醒）+ 群机器人 Webhook（群播报）+ 站内信兜底。2026-10 演进为智能机器人（aibot）形态：

- **群侧（已落地 · 2026-10-12 ~ 13）**：群通道定案（2026-10-12 · lan 代记 wmj）「群机器人 webhook → 智能机器人 + `chatid`」——Spike 结论：群回调稳定携带 `chatid`、846607 双语义拆清（未激活 / 超频）、限速实测 ≈ 30 条 / 分钟 / 会话（保守口径 = 按会话 30 条 / 分钟 · 1000 条 / 小时）、断连重连正常、激活前置 = 群内发过消息；M5-03-2 ~ M5-03-4 落地并收口（2026-10-13）——群通道（群播报 + 管理员告警出口）全链路真机闭环。
- **单聊侧（2026-10-13 项目组决定）**：单聊推送改走智能机器人（aibot 长连接）；**保留自建应用（`wecom_app`）实现作未启用备用通道**；接受「每个单聊先激活一次」成本。
- **关键实测（决定本决策形态）**：仅 enter_chat 不算激活（推送返 846607），用户发过消息后推送 errcode=0；单聊主动推送帧形（探针 send1）= `chatid` 填 userid + `chat_type` 1 + `msgtype` markdown（官方语义复核 + stub 锁帧 = 实现段首项）。
- **硬约束**：846607 双语义且 errmsg 不可区分 —— 须以激活态 + 本地限速分流；凭据（`WECOM_BOT_ID / SECRET`）只经 env / 仓外演练文件，不入库 / 日志 / 文档。

## 决策

> **2026-10-19 增补的适用关系**：单聊的「激活 / 寻址 / 未绑定降级」按下文「增补」节执行；原决策 3 / 4 中仍以「任意单聊消息 = 激活」为前提的表述，以增补为准。决策 1（通道形态）、2（渠道值）、5（回退）、6（与 ADR-009 关系）不变。

**总**：企微外发（群播报 + 单聊提醒）统一由智能机器人（aibot 长连接）承接；自建应用消息（`wecom_app`）保留为未启用备用通道。

具体条款（转写自执行计划 D1 ~ D6 / P1 ~ P3 定案）：

1. **通道形态（D1 / D2）**：单聊推送主通道改走 aibot；自建应用实现（`NotifyAppService` / `WecomClient` / token 缓存 / app 码表 / `WECOM_APP_*` env / 枚举值 / 路由分支）一律不删，作未启用备用通道。
2. **渠道口径（D5 / P1）**：新增独立渠道值 **`wecom_aibot`** 承载单聊 aibot（不复用 `wecom_app` —— 投递留痕语义与备用通道并存）；群维持 `wecom_group`；模板码一期**保名换渠道**（`R02_WECOM` / `R07_APP` / `A14_APP` / `A01_WECOM_MERGED` 不更名）。
3. **激活语义（单聊）**：激活 = 用户向机器人发过消息（enter_chat 不算 · 实测）；未激活 = **确定性失败**收口（846607 → dead + 同人站内信降级 · 幂等 `:c504`；不回退、不无界重试）；**不做激活表前置拦截**（先发 + 旁证回填，避免表滞后误杀）。
4. **降级指引（P3 · 业务定案 2026-10-14；话术终稿 2026-10-15 已回填）**：未激活降级站内信**前缀附激活指引话术** —— 终稿 = 「当前机器人未激活，请私发任意消息给机器人即可激活」（回填明细见 `M5-03 单聊执行计划` §8 v1.6）。
5. **回退（D6）**：4 条内置规则渠道值回切 `wecom_app`（纯代码 · 无数据迁移）；群通道路径与告警出口（B2）不动。
6. **与 ADR-009 关系**：本 ADR 承接 ADR-009 之「企微外发渠道形态」部分；站内信兜底、投递语义（Outbox 至少一次 + 幂等 + 限速 + 降级 + 死信 / 连续失败告警）、ChannelAdapter 适配位等其余口径继续有效。

## 增补（2026-10-19 · 绑定码与密文寻址）

### 增补背景与硬约束

- 智能机器人回调的 `from.userid`：**机器人创建者不是企业超级管理员时，为企业主体下的密文 `open_userid`**（官方口径 + 本仓 2026-10-16 实测 E1 ~ E7）；本项目拿不到企微后台管理员权限，无法改成超管创建机器人。
- 也无法用自建应用 `POST /cgi-bin/batch/openuserid_to_userid` 做密文 → 明文归一（需要自建应用 `access_token` 与成员可见范围，仍受管理员权限约束）。
- `users.username` 是 SSO 口径的**明文 userid**，企微单聊回调里不出现；因此**明文 userid ↔ 密文 open_userid 的映射只能由用户侧交互产生**。
- 产品口径：接受「每个用户对每个机器人先绑定一次」的成本；未绑定推送不再是目标，「未激活」不再作为单独的可投递前置。

### 增补决策

1. **单聊寻址（替代 `users.username`）**：单聊可投递地址 = `wecom_aibot_dm_activations` 中 `bot_id = WECOM_BOT_ID`、`bound_at` 非空、`user_id` 非空的 `wecom_userid`（回调原文 = 密文 `open_userid`）。`users.username` 仅保留 SSO 与 `wecom_app` 备用通道用途，**不再作为 aibot 单聊发送地址**。
2. **绑定码链路（一次性 · 用户驱动）**：用户在系统内取码 → 服务端签发 **6 位数字、全库唯一、一次性、TTL 5 分钟、与登录态 `user_id` 绑定**的绑定码；同一用户仅允许一个 `pending` 码，重发先作废旧码；生成频率 **5 次 / 3 分钟 / 用户**，罚时锚点 = 最近一码 + 3 分钟。
3. **绑定即激活**：用户在机器人单聊中发送该码，长连接回调命中后，同一事务内完成「占码 `pending → used` + 写入/改挂绑定行 `(bot_id, wecom_userid) → user_id`、`bound_at`」，并回「绑定成功」。发码本身就是给该机器人发过消息，**绑定行同时是激活态与投递地址**。
4. **非码单聊消息**：仍登记激活（`user_id` 可空、`bound_at` 为空），用于 846607 双语义分流与观测，但**不可作为发送地址**；未命中任何码的正文不回复（防探测），正文不入库、不落日志。
5. **未绑定降级（D4 终稿）**：收件人无绑定行 → **不发帧**，按确定性失败 `dead` 收口，并降级同人站内信，前缀 = 「当前用户未绑定企业微信，请前往设置补绑」。该话术替代原「当前机器人未激活，请私发任意消息给机器人即可激活」。
6. **换绑与幂等**：绑定态以**码持有者**为准；同一企微号从旧持有者改挂到新用户 = 跨用户换绑，与绑定行改挂同一事务写 `audit_logs`（`objectType=user` / `action=update`，摘要与变化只带掩码）；解绑写 `action=delete`。`used` 码重复回调且绑定仍归本人 → 幂等回「绑定成功」；码过期或已被他人使用 → 「码已失效，请重新获取」。
7. **机器人维度**：绑定行按 `(bot_id, wecom_userid)` 唯一；`open_userid` 跨机器人稳定，但**激活 / 绑定按机器人成立**。换机器人 = 新 `bot_id` 下无绑定行，用户重绑一次即可；**不需要清空整张激活表**（旧 `bot_id` 行保留历史；迁移 0055 只清理 `bot_id` 为空的历史遗留行）。
8. **安全与最小暴露**：`open_userid` 虽是密文但仍属个人标识；日志、绑定态读面、审计摘要一律只留掩码；绑定码正文不入库、不落日志；机器人 `WECOM_BOT_ID` / `WECOM_BOT_SECRET` 只经 env / 仓外演练文件，**不入库、不日志、不文档**。
9. **口径演进**：早期绑定码口径的「TTL 10 分钟 / 3 次每小时」是过渡值，已由 D3 v1.8 / v1.9 修订为 **TTL 5 分钟 / 5 次每 3 分钟**；以本增补与 `M5-03-5` 口径 v1.9 为准。

### 与原决策的关系

- **决策 1 / 2 / 5 / 6 不变**：通道仍由 aibot 承接；单聊渠道值仍为 `wecom_aibot`；回退仍为 4 条规则回切 `wecom_app`；ADR-009 仅「企微外发渠道形态」部分被承接。
- **决策 3 细化**：原「激活 = 用户向机器人发过消息」继续描述会话激活事实；但**可投递资格**改由绑定行决定 —— 非码消息只登记激活，绑定码才写入 `user_id` / `bound_at`。原「不做激活表前置拦截」不再适用于绑定判定：投递前以绑定行为唯一判据，无绑定行直接确定性失败 + 降级，避免向不可达的密文地址发帧。
- **决策 4 替换**：未绑定降级话术以 D4 终稿「当前用户未绑定企业微信，请前往设置补绑」为准；原「请私发任意消息激活」仅保留为历史表述。

### 备选与不采用原因（增补）

- **继续用 `users.username`（明文 userid）作为单聊发送地址**：回调只给密文 `open_userid`，无管理员权限无法建立明文映射；且会把 SSO 标识与企微投递地址耦合 —— 不采用。
- **申请超管 / 自建应用批量换算 `openuserid_to_userid`**：当前拿不到企微后台管理员权限，路径不可执行 —— 不采用（若后续权限变化，按切换触发条件重新评估）。
- **不落库、只用内存或签名令牌承载绑定码**：6 位数字空间小，无法安全编码 `user_id`；也无法可靠实现一次性占用、过期、限流、幂等与审计 —— 不采用。
- **绑定成功后立即删除绑定码行**：会丢失重复回调幂等、误绑审计、限流计数与防重放依据；一次性语义应由 `pending → used` 状态保证，而不是删除 —— 不采用。
- **换机器人时清空整张激活 / 绑定表**：`open_userid` 跨机器人稳定，且行已按 `bot_id` 隔离；清表既无必要，也会丢失历史与审计线索 —— 不采用。

### 影响与后果（增补）

- **数据模型**：迁移 `0055` 新增 `wecom_id_binding_codes`（`code` / `user_id` / `status` / `expires_at` / `used_at` / `used_wecom_userid` / `created_at`）；`wecom_aibot_dm_activations` 增 `bot_id` / `bound_at`，唯一键改为 `(bot_id, wecom_userid)`。无手工 SQL、无表清空步骤。
- **契约与实现**：新增取码 / 查绑定态 / 解绑三端点；单聊发送路径由 `users.username` 改读绑定行 `wecom_userid`；未绑定 → 不发帧 + 站内信降级；跨用户换绑与解绑写 `audit_logs`（仅掩码）。
- **运营**：机器人可用范围须覆盖全部系统用户；每个用户对每个机器人首次使用需完成一次绑定；未绑定用户在通知相关页面看到补绑提示。
- **回退**：按 D6 将 4 条内置规则渠道值回切 `wecom_app`；绑定码表与绑定行可保留（非破坏性），无需回滚迁移 0055。
- **文档同步**：`系统功能书.md` / `字段对照清单.md` 中 Push 247 / 249 的「TTL 10 分钟 / 3 次每小时」为过渡值，最终以本增补及 `M5-03-5` 口径 v1.9 为准；建议 px 在下次文档回填时统一订正。

## 备选与不采用原因

- **维持 ADR-009 原形态（应用消息单聊 + 群机器人 Webhook）**：群侧已随 M5-03 切换（定案 + 真机收口）；单聊侧项目组决定改走 aibot —— 不采用；应用消息保留为备用而非主通道。
- **原地修订 ADR-009（不立新 ADR）**：与 ADR 规则 2「决策变更不修改历史结论 —— 新增 ADR，并在旧 ADR 标注被取代」不符；不采用（承接先例 = ADR-030 → ADR-007）。
- **复用 `wecom_app` 枚举值承载单聊 aibot**：投递留痕语义失真、备用通道无法并存 —— 不采用（新增独立值 `wecom_aibot`）。
- **未激活时回退自建应用发送 / 无界重试**：双栈维护成本与重试风暴风险 —— 不采用（D3 确定性失败 + 站内信降级）。
- **激活表前置拦截（未命中不发）**：表滞后会误杀已激活用户 —— 不采用（D4 先发 + 旁证回填）。

## 影响与后果

- **ADR-009 → 部分被本 ADR 取代（Superseded · 2026-10-14）**：仅「企微外发渠道形态」部分；其余口径见决策 6。
- **契约 / 实现**：`NOTIFY_CHANNELS` 增 `wecom_aibot`；4 条内置规则渠道值切换（R02 / R07 / A01 / A14）；`notify_deliveries.channel` CHECK 扩值（迁移 0048 —— 0047 已用于内容译文库）；投递白名单 / outbox 路由新增分支；新增单聊激活表；模板码保名（P1）。
- **运营**：机器人启用范围须覆盖接收人；单聊每人首次激活一次（指引话术进降级站内信前缀 + 依赖清单运营项）。
- **安全**：凭据只经 env / 仓外演练文件；不入库 / 日志 / 文档。
- **回退**：4 条规则渠道值回切 `wecom_app`（纯代码）；群通道路径与告警出口不动。

## 切换触发条件

- aibot 形态不可行（接口下线 / 单聊发送语义变化 / 激活成本不可接受）→ 按回退规则（D6）切回应用消息，并重新评估本决策；
- 其他部门使用不同 IM → 沿用 ADR-009 适配位（ChannelAdapter）启用新通道实现。
