## 背景

文件是本项目最重的一类资产：图纸与三维文件常见几百 MB，需要预签名直传、分片与断点续传、版本控制、生命周期与异地备份；同时「不允许上传第三方云」是业务硬约束。

## 决策

- **接口层（2026-09-18 定，不变）**：全部代码只依赖 S3 协议接口，封装在文件 / 存储模块内，实现可替换。
- **一期实现（2026-09-21 修订）**：不再把 MinIO 社区版锁定为一期实现（阶段 0 核实：上游归档、官方分发下线，见下）。落地口径：
  - **本地沙箱 / 联调**：固定版本容器 `quay.io/minio/minio:RELEASE.2025-09-07T16-13-09Z`，**仅沙箱，不代表生产选型**；
  - **生产实现**：按候选顺序关闭 —— ① 公司内网既有对象存储 / 既有 MinIO 集群（若确有：运维能力现成、风险最低）；② SeaweedFS（Apache-2.0，活跃维护）等自建 S3 兼容实现；③ 公司云 OSS（受「不允许上传第三方云」约束，需先有云策略结论）；
  - **关闭责任与时点**：px（运维：环境 / 合规 / 容量）+ lan（平台：兼容性）在 M8 生产部署形态验证前关闭；关闭验收 = `npm run storage:init -- --check` + `npm run storage:it` 在目标实现上全绿（即「实现可替换」的证明）。
- **工程要点**：
  - 浏览器经 api 申请预签名 URL 直传，api 不代理大文件流量；
  - 预签名 URL 的 host 必须对客户端可达（外网 / 内网两种部署形态在阶段 0 用真实网络验证）；
  - **对象键形态（2026-09-21 定案）**：`projects/{projectId}/files/{fileId}/v{seq}/{contentHash}.{ext}`（键含版本与内容哈希，定档不覆盖物理对象）；上传会话先写**暂存键** `projects/{projectId}/files/{fileId}/staging/{sessionId}`，`complete` 校验分片与哈希一致性后由服务端复制（CopyObject）到契约键、再删暂存对象，落库的 `file_versions.object_key` **始终是契约形态**。代价：完成时一次服务端复制（对象瞬时双份）；单对象 > 5 GiB 需 UploadPartCopy —— 一期由服务端上限挡在 5 GiB 以内（`UPLOAD_MAX_SIZE_MB`，PoC 验收为 200 MB 级），放开上限时再补；
  - **能力差异登记（替代实现必须满足的行为面）**：CORS 与生命周期规则**不得**成为唯一手段 —— CORS 可走服务端配置（如 `MINIO_API_CORS_ALLOW_ORIGIN`）或反向代理补响应头；未完成分片由存储侧兜底清理（如内置 `stale_uploads_expiry`），草稿 / 临时文件的 30 天清理由应用侧（`files.purge_after` → worker）驱动；
  - 「定档」在数据库层锁版，物理层不覆盖；
  - 原文件名（含中文）存元数据，不进对象键；
  - **数据库备份成功不等于文件备份成功**：恢复演练必须数据库 + 文件同时恢复，并抽检「任务 → 附件 → 哈希」链路。

| 版本 | 锁定 `RELEASE.2025-09-07T16-13-09Z`（commit `07c3a429…`，go1.24.6 linux/amd64），镜像来自 `quay.io/minio/minio` |

## 备选与不采用原因

- 云对象存储（OSS / COS / OBS）：运维最省，但图纸可能不允许出内网（合规待公司云策略），作为后续替换项。
- NAS / 本地盘：不作为主存储，仅作异地副本目标。
- **「暂存键即版本键」（2026-09-21 不采纳）**：对象键不再包含版本与内容哈希，与契约 `FileVersion` 描述及本 ADR 工程要点冲突（改键 = 改契约，不是「只差一个键构造器」）；且暂存对象与定档对象无法用存储侧规则区分（误删风险落到人工）。采纳的是「暂存键 → 完成时复制到契约键」。

## 影响与后果

- 生产实现**未关闭前**，文件上传 / 预览不得按「生产可用」对外演示；沙箱 MinIO 不得用于生产。
- 文件生命周期与版本语义成为产品行为的一部分（临时清理、定档不可变）；**清理不依赖存储侧 lifecycle 规则**（沙箱已证不可用），由应用侧任务驱动。
- 版本与内容哈希进键，历史对象天然不可变；完成时多一次服务端复制，属可接受的一次性固定成本。
