# ADR-027 项目归档：冻结状态位 + 引用式清单（不做全库快照表）

- 状态：草案（Proposed）｜评审：lan、px｜随 PR 合并 main 后转「已采纳（Accepted）」
- 日期：2026-09-20｜决策人：wmj（技术负责人）
- 依据：技术设计v0.3-实施与验收.md §7#12、§3.6 / §3.7；技术设计v0.2-架构与数据模型.md §2.4 / §11.2；系统功能书.md C4-01 / C4-02 / C4-03 / C4-04 / C4-07

## 背景

业务要求验收完成后一键归档、冻结数据快照（任务、文件、变更、日报、问题），并解决「变更历史无法及时留存」。但一期没有「归档后继续查询历史版本」的需求，全库复制式快照表会带来双份数据、迁移与清理成本；需要的是「冻结 + 可检索的清单」。

## 决策

- **归档前置（2026-11-12 修订）**：项目内未删除任务全部 done 即可归档；不再要求验收阶段推进、文件定档或必交成果齐全。存在未完成任务时返回 409 `ARCHIVE_NOT_READY`，`confirm=true` 不可越过；文件与缺项类 422 仅保留历史兼容。
- **冻结 = 状态位**：归档即 projects.status 置 archived（0001 基线已有枚举），此后所有写路径（任务 / 节点 / 文件 / 变更 / 成员）统一拒绝，写保护错误码随 M0-02 切片登记；同时撤销进行中的上传会话。
- **归档清单 = 引用式快照**：归档动作生成一份清单记录（归档时点、操作人、统计口径：任务数与状态分布 / 阶段状态 / 文件清单含版本 / 变更记录 / 日报 / 问题），清单只记 id 与摘要，**不复制全量业务数据**；归档不删除任何数据、不改变阶段。
- **导出**：一期只做归档目录结构 + 清单（C4-03）；压缩导出包（含文件、可选 PDF 目录册）属二期 C4-04。
- **可检索**：归档项目与清单进入搜索投影（C4-07），按现有权限过滤规则返回。
- **权限与留痕**：仅最终项目编辑者（管理员、所管本项目的项目经理或规则 edit）可归档；归档与解冻（如需，一期不开放）都写审计；归档不清空回收站，文件清理仍按 A4-12 的 30 天口径执行。

## 备选与不采用原因

- 全库快照表（复制任务 / 文件 / 变更等全量数据）：双份数据、成本高、无查询场景，不采用。
- 只读视图 / 只加标记：没有冻结语义，写路径仍可改，不采用。
- 归档即导出压缩包：大文件体量与耗时不可控，二期再做，不采用。

## 影响与后果

- 新增表：project_archives（清单记录，随 M6 / M7 卡片）；v0.2 §11.2 中「projects 归档只读状态位」条目据此细化。
- 写保护需在所有写路径统一（与软删写保护共用一处 guard），并有拒绝用例（归档后写 → 409）。
- 搜索投影需覆盖归档对象（C6-04 同事务维护口径不变）。
- 归档提醒（A18：项目任务全部完成后 7 天未归档提醒）依赖本 ADR 的归档判定。

## 切换触发条件

业务要求归档后继续变更（版本化归档）或需要跨系统交付归档包时，评估归档版本表与导出管道（C4-04）。
