# ADR-042：企微智能机器人日报查询

- 执行基准：`docs/企微智能机器人日报查询实施方案.md`（活文档，负责执行中的口径、切片与工期变更）

## 背景

项目成员需要在企业微信智能机器人中按项目、日期查询某一天的日报和问题。现有 `group-sync` 是项目经理主动同步单篇日报的通知链路，带有版本去重、审计、outbox 和群播报副作用，不能作为按人权限的即时只读查询。若直接复用，还会把“项目经理通知”误当成“成员查询”，权限和失败语义都不成立。

同时需要解决：单聊与群聊的发送人身份映射、项目重名、群内数据暴露范围、按日问题口径、单篇与多篇海报、单聊主动发送图片，以及图片失败不能拖垮整次查询。

## 决策

- **入口与命令**：单聊、群聊均支持确定性命令 `查询 [项目] <项目编号或项目名称> [日期] [日报|问题|日报和问题]`。默认日期为今天、默认主题为日报和问题；日期按 `Asia/Shanghai` 解释并拒绝未来日期。以“查询”开头的消息必须先于单聊绑定码提取处理，语法错误只返回命令帮助，不进入绑定码链路。第一版不接大模型、不做自然语言自由问答。
- **身份与权限**：两端都以 `(bot_id, from.userid)` 映射单聊绑定行。P0 已在测试环境确认同一用户的群回调 `from.userid` 与绑定行 `wecom_userid` 一致。发送人必须拥有项目 `report.view`；查询问题内容、数量和问题海报还必须有 `issue.view`，否则只返回日报部分。项目不存在、不可见、无 `report.view` 使用统一错误口径，不泄露资源存在性。
- **项目解析**：支持 `projects.code` 与归一化后的项目名称精确匹配，不做模糊搜索。单聊按名称命中多个发送人可见项目时，只回复带编号的重名提示，不返回任何业务数据。群聊只允许查询群绑定项目；未显式指定项目时使用群绑定项目，显式指定其它项目时拒绝。
- **数据口径**：在 `report-issue` 增加只读 `ReportDigestService`，返回查询日快照：已提交及补填日报逐篇返回，草稿只返回数量、正文与附图不返回；问题按 `issues.raised_at = 查询日期` 查询，包含自动生成和手工创建的问题，不还原历史状态。文字与两张海报共用同一快照，并在只读事务内读取。附件元数据批量读取，只有海报阶段读取字节。第一版不新增业务表。
- **输出顺序**：先被动回复自包含文字与当天日报深链，再依次发送日报图、问题图；每次查询最多两张逻辑图片。恰好一篇已提交日报时复用现有日报海报与问题专报视觉；两篇及以上时新增日报合集海报与问题合集海报。多篇日报的深链增加 `date=YYYY-MM-DD` 精确定位，单篇继续使用 `report={reportId}`。
- **单聊图片（方案 A）**：先用 `replyToCallback` 回复文字，再通过现有上传接口取得 `media_id`，新增 `sendUserImage` 以 `chat_type=1` 主动发送图片；帧内 `chatid` 使用绑定行中的密文 `open_userid`。上传失败分类必须按单聊 / 群聊渠道路由，不能固定为 `wecom_group`。`messagesEnabled=false` 仅表示不接受主动提醒，不阻断用户主动发起的查询回复。
- **失败降级**：图片渲染异常、超过 10MB、附件 / 分片校验失败、上传或发送失败、限流拒绝、并发闸门拒绝时，只跳过对应图片并记录内部日志；日报图失败后仍尝试问题图。文字和深链必须自包含，不允许因图片失败整次查询失败或重发已送达文字。
- **限流与幂等**：同一发送人 / 项目群建议 5 秒最多一次查询；海报全局同时渲染 1 张、排队最多 2 个。第一版以 `bot_id + msgid` 做 10 分钟、容量 1000 的进程内 LRU 去重；多 worker 前必须升级为数据库幂等。
- **模块边界**：新增仅由 worker 引入的 `report-query` 组合模块，依赖 `PermissionModule`、`ProjectModule`、`ReportIssueModule`、`NotifyModule`。查询是只读链路，不写审计、outbox、站内信或群播报；`notify` 不得反向 import `report-issue`。`group-sync` 与 `syncToProjectGroup` 不复用。
- **功能开关**：新增 `WECOM_REPORT_QUERY_DM_ENABLED` 与 `WECOM_REPORT_QUERY_GROUP_ENABLED`，只接受字符串 `true` / `false`，默认均为 `false`；关闭时完全保持现有回调行为。测试机按“单聊 → 群聊”顺序开启，正式机在测试验收通过后再开启。

## 备选与不采用原因

- 复用 `group-sync`：它的项目经理权限、单篇限制、版本去重和通知副作用与成员即时查询不一致。
- 群聊跨项目查询：会让群成员看到超出群绑定项目的数据范围。
- 图片失败导致整次查询失败：深链文字已经能提供完整结果，图片只是增强。
- 依赖大模型解析命令：确定性命令更易测试、审计和限制权限。
- 用日报派生问题代替按日问题：会漏掉手工创建的问题；也不能用日报条数冒充问题总数。

## 影响与约束

- wmj 负责新增读面、项目解析和按日问题查询；lan 负责查询编排、单聊图片与海报合集；px 负责前端日期深链及 `前端功能需求.md`。跨线契约、权限和字段口径变动先对齐归属人。
- 群聊面向整个群可见，必须保持“仅群绑定项目”的硬限制；日志、错误文案和审计不得包含正文、完整 `open_userid`、`chatid` 或对象存储细节。
- 多篇 Canvas 海报需要内容预算和并发闸门，避免阻塞 worker；渲染后必须检查字节数，超过单图 10MB 只跳过该图。
- 进程内幂等只适用于单 worker；水平扩容前必须另立迁移，将幂等持久化。
- 本 ADR 记录决策，不承接执行状态变化。实施中的命令、权限、数据口径、图片策略、切片或工期变化，直接更新执行基准活文档及其变更记录。

## 切换触发条件

- 业务要求自然语言自由问答或非确定性意图识别时，重新评估是否引入受控模型解析；确定性命令入口仍保留为可测试兜底。
- 群聊需要跨项目查询、或权限模型 / 群绑定关系改变时，必须重新评审群内数据暴露边界。
- 企微单聊主动图片接口、10MB 限制或频控规则发生变化时，重新评估方案 A 与失败降级矩阵。
- 部署进入多 worker / 多实例前，重新评审进程内幂等与海报渲染闸门。

## 验证

- S0：`server/test/env-access.test.ts` 验证两个开关缺省为 `false`、可独立指定 `true` / `false`、拒绝 `0` / `1`；`server` typecheck、build、边界检查和定向测试通过。
- S1：`ReportDigestService` 在 `repeatable read` + `read only` 事务内读取项目、当日日报、按日问题与批量附件元数据；`report-digest.test.ts` 覆盖草稿排除与计数、补填、同人同日多篇稳定排序、手工 / 派生问题、批量附图与空态；`project-query.test.ts` 覆盖编号、名称归一化、重名、不可见项目过滤与群绑定约束匹配。server 全量 113 文件 / 1667 项通过，typecheck / build / boundaries / permission-matrix 通过。
- S1–S3 已落；S4–S7：按执行基准继续覆盖单篇/多篇海报、10MB 与全图片失败降级。S3 已覆盖查询优先于绑定码、群聊仅激活、项目重名、`report.view` / `issue.view` 隔离、深链、5 秒限流与 `bot_id + msgid` 幂等。
- 测试机先开单聊并复验身份映射，再开群聊验收；正式机在测试机通过后按同一顺序开启。
