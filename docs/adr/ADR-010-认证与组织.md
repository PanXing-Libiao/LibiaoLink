# ADR-010 认证与组织：公司统一 SSO（Casdoor，OIDC + PKCE）

- 状态：草案（Proposed）｜评审：lan、px｜随 PR 合并 main 后转「已采纳（Accepted）」
- 日期：2026-09-18｜决策人：wmj（技术负责人）
- 依据：技术设计v0.1-选型分析.md §0.1、§4.11、§5（#11）；docs/ 下 SSO 方案 / 接入标准 / 实测报告

## 背景

公司统一登录（Casdoor，自托管身份中心）已上线，有接入标准与本地 / 公司环境实测记录；业务要求统一走企微登录，各系统不自建账号。

## 决策

- **一期唯一登录方式**：公司统一 SSO（Casdoor，OIDC authorization_code + PKCE + state）；本系统只做 OIDC 客户端，不自建账号 / 密码 / IDP。
- 企业微信为账号来源之一，由 Casdoor Provider 承接；本系统不直连企微做登录。
- JWT 标准字段：Name（工号）/ DisplayName / Email / Id / Owner；不使用 Casdoor SDK，只用标准 OIDC。
- 会话：生产用 HttpOnly Cookie + CSRF 同步 Token；会话表在 PostgreSQL，不存原始凭据；登出同时清本地会话并跳转 Casdoor 统一登出。
- /auth/login、/auth/callback、/auth/me、/auth/logout 一期由前端 Vite 中间件承载（仅开发）；已于 k6（Push 46）迁到后端 identity 模块，开发与生产同一条链路。
- 认证与授权分离：Casdoor 不下发业务角色（默认为空），业务权限由 ADR-011 的本地策略层负责。
- 组织同步：依托 Casdoor + 企微通讯录（离职自动禁用），本地按工号 / 用户 ID 建映射表；未认证一律 401 并跳转 SSO。

## 备选与不采用原因

- 自建企微 OAuth + 本地账号兜底：仅当 SSO 不可用或不覆盖外部干系人时启用（干系人不发账号，见系统功能书口径）。
- AD / LDAP / 钉钉 / 飞书登录：由 Casdoor 侧对接，本系统无感。

## 影响与后果

- 本系统无登录页、无密码管理、无找回流程——这些责任在 Casdoor。
- 离职回收链路的时效依赖 Casdoor + 企微通讯录的准确性。
- 前端与会话相关的所有改动属高风险变更（CONTRIBUTING §15），需非作者评审。

## 实现回写（g6，2026-09-18）

- 路由实现：`server/src/modules/identity/auth.controller.ts`（`/auth/login`、`/auth/callback`、`/auth/me`、`/auth/logout`）；契约 `shared/src/modules/identity.ts`；前端 Vite 中间件已于 k6（Push 46）移除，/auth/* 由后端承载。
- 会话存储口径：Cookie 仅携带不透明令牌，`sessions.token_hash` 只存 sha256 哈希；`sessions.id_token` 仅用于 Casdoor 单点登出（`id_token_hint`）；不存 refresh_token / access_token / client_secret。
- 超时口径：`SESSION_IDLE_MINUTES`（默认 30 分钟，接入标准「企业内部系统」档）+ ID Token `exp` 绝对上限；超时 / 撤销 / 禁用后 `/auth/me` 返回 401（前端无感重新认证）。
- 退出与 CSRF：登出撤销本地会话并 302 到 Casdoor `/api/logout`；登录下发 CSRF Cookie，`/auth/me` 同时返回同一同步 token（`no-store`），写接口经 `CsrfGuard`（double-submit）校验。这样即使 WAF 将 `ll_csrf` 改写为 HttpOnly，前端仍能取得 token；失配返回 `CSRF_FAILED`，不记作越权。
- 测试基座：进程内桩 IdP（discovery / JWKS / 换令牌，RS256 真签名）+ 内存仓库（DB-free），10 例端到端见 `server/test/auth.e2e.test.ts`。

## 切换触发条件

SSO 不可用或不覆盖外部干系人时，启用备用登录方式（企微 OAuth / 本地账号兜底），并升级本 ADR。
