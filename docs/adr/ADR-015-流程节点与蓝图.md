# ADR-015 流程节点与蓝图：自研节点体系 + 自建蓝图 JSON 格式（不引入 BPMN 引擎）

- 状态：草案（Proposed）｜评审：lan、px｜随 PR 合并 main 后转「已采纳（Accepted）」
- 日期：2026-09-18｜决策人：wmj（技术负责人）
- 依据：技术设计v0.1-选型分析.md §4.21、§5（#16）、§9；技术设计v0.2-架构与数据模型.md（蓝图 / 节点模型）；2026-09-17 业务口径确认

## 背景

业务需要一个受控的项目执行过程：公司标准流程（九阶段：售前规划 → 设计开发 → 加工采购 → 组装发货 → 硬件实施 → 软件部署 → 试运行 → 投产阶段 → 验收）连同阶段下的节点、顺序、约束（含必交成果物）整体定义成可复用的模板。本质是业务数据 + 校验规则，不是通用流程编排。

## 决策

- **自研节点体系**：固定模板不可在项目内随意编辑；项目按模板导入生成节点实例，节点可按模板规则增删（一期仅限模板节点池，增删留痕、受约束校验）。
- **节点约束数据化**：每个节点至少一类约束（必交成果物 / 完成条件 / 前置节点 / 时限）；约束是可配置数据，不写死在代码里。
- **完成门禁（服务端强制）**：节点声明必交成果文件时，文件缺失不允许完成——UI 置灰 + 原因提示；服务端事务内强校验，拒绝返回 422 + missing 明细；绕过尝试留痕。
- **自建蓝图格式**：JSON schema（schemaVersion + 蓝图版本号 + 适用条件字段保留 + 阶段数组 + 节点数组（顺序 / 约束 / 必交成果物引用）+ 校验规则）；导出 / 导入同格式、round-trip 无损；快速导入 = 新建项目时一键生成整套阶段 / 节点 / 约束。
- **导入校验**：schema 校验 + 引用校验（成果物类型、字典项必须存在）+ 幂等（同一蓝图版本重复导入不重复生成）+ 导入留痕（谁、何时、从哪个版本）。
- **口径（已确认）**：蓝图全局一份；**蓝图变更不影响已生成项目**（导入即快照，项目内调整走增删并留痕）；一期节点体系不做权限控制（ADR-011 例外）；自定义节点与管理员权限留待后续版本。

> 修订（2026-09-20 · M0 决议，Push 71）：其中「蓝图全局一份」由 **ADR-019** 修订为「按项目类型各一份 + 默认模板兜底」；「一期节点体系不做权限控制（ADR-011 例外）」由 **ADR-020** 修订为三档权限（模板管理员 / 项目内增删项目经理 / 完成回退平权）。历史结论保留，执行以 ADR-019 / ADR-020 为准。
- 与自动化关系：节点状态变化（完成 / 逾期 / 缺件）是规则触发器；门禁管「不能完成」，提醒规则管「催办」，两者互补。

## 备选与不采用原因

- 轻量工作流引擎 / BPMN：节点模型是业务数据 + 校验规则，引擎带来的是通用编排能力与额外的模型 / 运维成本；门禁必须可单测、可金标回放，自研更可控。
- 外部流程格式导入（Visio / WPS / Excel 流程图）：格式不受控、无法承载约束语义，不采用。

## 影响与后果

- 门禁是产品正确性的一部分：全部判定在服务端事务内完成，前端只做预检展示（can-complete）。
- 节点约束细则（哪些节点必交哪类成果文件、能否回退）属业务待确认项（Q28），不阻塞本决策。
- 蓝图 round-trip 与门禁拒绝行为是阶段 0 必过 PoC（PoC-9）。

## 切换触发条件

出现跨系统流程编排、多套蓝图并行编辑冲突，或业务需要可视化流程设计器时，重新评估引擎方案。
