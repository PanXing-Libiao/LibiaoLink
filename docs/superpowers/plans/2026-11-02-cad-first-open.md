# CAD 首开与后台调度实现计划

目标：缩短已缓存产物的资源读取等待，优先处理正在查看的任务，并使首开各阶段耗时可定位。

## 契约与范围

- CAD 专项由 wmj 承接；覆盖 CAD 队列、预览窗口、查看器传输和诊断。现有权限、文件版本隔离、摘要校验及完整性声明保持有效。
- 队列复用原任务。窗口打开和等待期间状态轮询维持 30 秒活跃期，取消立即失效；超过 5 分钟的可执行任务优先于新前台任务，防止静默队列饥饿。不抢占正在解析的任务。
- buffer 按 SHA 去重，最多 4 个并发请求、32 MiB 在途声明字节；单个超过窗口的合法 buffer 独占下载。总产物限制不放宽。任何失败中止其余请求，所有请求结束后释放租约。
- 首开计时沿用查看器诊断，不增加用户操作：任务创建、观察到的排队/处理/保存等待、清单读取、数据展开、几何传输、视图构建、首帧及可交互。浏览器观察值不冒充服务器执行耗时；worker 另记录实际处理阶段耗时。

## 实施与验证

1. 先补传输行为测试和真实 PostgreSQL 队列排序测试，确认旧实现不能满足新规则。
2. 增加窗口心跳列和索引（追加迁移），迁移测试夹具及调用方；覆盖多人窗口、取消、失联、退避和竞争领取。
3. 实现有界下载与去重，覆盖摘要冲突、失败取消、租约释放和共享只读字节。
4. 接入现有诊断计时，验证缓存命中与等待路径；同步需求、字段清单、运行说明和发布身份。
5. 跑相关测试与仓库推送前检查，更新开发日志，推 wmj、创建 PR；当前 head 全部 CI 与实际门禁通过后 squash 合并，保留 wmj。

## 本地验证结果

已完成实现与定向验证：Node 8 项、服务和真实 PostgreSQL 46 项通过；前后端类型检查、前端构建、发布身份校验通过。内置浏览器在受控 DXF API 夹具下验证等待路径与缓存命中；未测真实公司图纸的性能提升比例。发布前须先应用迁移 0080。
