# DXF 二维范围补全与验证

> 换机检查点（2026-10-27）：以下为 DXF v0.15.0 的既有收口记录。用户随后授权将当前 CAD 基础与独立 DWG 工作推送 `wmj`，不部署；此后不主动扩展 DXF。DWG 不经过 DXF，最新状态见 [原生 DWG 交接](../../../server/cad-engine/DWG_HANDOFF.md)，当前公共代码 release 以 `source.json` 为准，不能沿用本文件历史摘要冒充最新发布。

目标：持续处理已确认的二维实现缺口，选择性改写成熟社区机制，沿用源记录身份、上传资源边界、UCD 派生几何、共享投影和拾取/裁剪；不以任意批次结束。三维内核、DWG 主图、CAD 编辑器及无法取得的原资源不纳入二维显示承诺。

基线：本地 DXF v0.14.0，release `74245822040c780b08601eb37a92f16a9efdab2f5129bfc681a23997783d7a37`；98 项 DXF、6 项 schema、8 项裁剪、1 项 release 回归及 48 项浏览器检查。该基线不代表任意 DXF 或独立 AutoCAD 验收。已有工作区修改保留，当前会话不提交、推送或部署。

方法：在责任层实现并迁移消费者；不能把异常转换为成功空图。源数据、派生显示与工程语义分别计证据。字体、外参、图片、打印样式只能读取明确上传字节，不访问源文件声明的任意磁盘/网络路径。新源语义采用明确的事实、引用及计算来源，不声称拥有 CAD 求解器。

## 方案取舍与已知证据

- 打印样式优先使用仓内 ezdxf 1.4.2 `addons/acadctb.py`，无需引入整套社区查看器。
- ACIS API 只能处理已知结构，未知实体会变成 NONE；因此必须先检查解析完整性，再声明平面 REGION 可显示，不能把读取成功等同完整内核。参考官方文档：https://ezdxf.readthedocs.io/en/stable/acis.html。
- GDAL 内置 DGN 驱动仅支持 v8 以前，样条不准确、文本输出为点且不保留单元关联；不能直接当作完整底图显示方案。DGNv8 依赖 Teigha。参考：https://gdal.org/en/stable/drivers/vector/dgn.html。
- 已登记 truedxf `019c2e504738965c17818a5780097fef0e7a52f4` 可继续作为选择性适配来源；仅取需要的模块/规则，保留许可和版本，不整体拉取应用。

## 仍未覆盖及需要的具体条件

这些是当前实现边界，不能统一解释为“只缺原件”，也没有标为已完成：

| 剩余范围 | 当前处理与原因 |
|---|---|
| 缺失原资源、源几何本身为空 | 列出原路径/句柄和缺失原因。需实际上传原字体、形状库、外参或媒体；空引线没有可恢复的端点，不生成猜测几何 |
| 非文字注释上下文 | 保留完整源图并明确 partial；INSERT/DIMENSION/其他类型的专有位置尾部、默认状态与变换规则尚未实现。公开读取器存在字段次序/含义冲突，现有实测原件不足以核验，不能把它们当普通缩放。需要对应二维源上下文和原 CAD 对照 |
| DGN V8、V7 RSC 字体/共享单元/自定义线型及未还原曲线 | 当前轻量读取器没有完整的原调色板、字体映射、实例变换和曲线语义证据；整个底图明确未显示，不能只发布支持前缀。完整 SDK 路线涉及单独运行时/授权，未冒充现有依赖能力 |
| 未知 ACIS 程序曲线；OLE 非 CF_DIB 内容 | 现有 REGION 只解释可验证的显式曲线；olefile 仅提供存储读取，未提供 EMF/WMF/原应用渲染器。这些仍是实现缺口，需要能保留原语义的解码器与实际字节回归，不能靠折线或空缓存替代 |
| 应用 FIELD、动态块重新生成、约束/验收计算 | 保存当前状态、参数/关联图和源缓存；没有原应用评价器或 CAD 求解器，不执行任意回调或把显示数值作为工程结果 |
| 原 CAD 精度与实际打印 | 复杂竖排/混排、渐变拟合、底图放置、菱形端点/连接、PC3 设备抖色尚无本项目独立原 CAD 对照；屏幕预览不代表实际出图。合成像素检查不能关闭这一项 |
| 目标 Linux 及公司环境 | 本轮实际 native worker 验证在本机完成；未构建/运行目标 Linux 镜像，未部署。新增依赖已锁定，不能把本机通过写成目标环境验收 |
