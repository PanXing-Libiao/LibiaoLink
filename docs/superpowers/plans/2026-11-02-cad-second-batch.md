# CAD 第二批：主线程减负与产物生命周期

## 选择与边界

- 先测 JSON 解码与 packed/compact 元数据展开。大清单由同源 module Worker 接收可转移 ArrayBuffer，复用现有展开函数，返回普通 UCD 对象；小清单保留直接路径，避免线程启动和复制成本。不迁移 Three.js/DOM 状态，不改变完整性、几何或拾取契约。
- 最近使用以真正打开窗口的时间持久记录；后台预热不能把文件变成“最近使用”。空闲队列每分钟最多预热两个近七天使用、缺少当前格式任务的输入集合，保留编码和配套版本。当前任务失败不自动反复复活。
- 回收仅针对同一输入集合已有当前格式就绪替代品的旧格式产物；旧任务仍执行或存在未过期窗口/租约时保留。锁定产物并重新检查后，事务内移除旧记录并登记精确前缀的持久删除任务，延迟一天删除，失败保留以便重试，不扫描/删除原文件或全库重算。
- 生命周期维护只在 CAD 队列空闲时执行，每分钟最多两项预热、两项退休和两项删除；不增加解析并发。新表/列先迁移再发布。

## 验证与交付

测量受控大清单，比较主线程与 Worker 的阶段时间和响应间隙；检查取消、损坏清单、失败、相同输出及租约行为。真实 PostgreSQL 验证访问记录、预热隔离、就绪替代条件、活动引用、并发与持久删除重试。同步需求、字段清单、运行说明、发布身份及开发日志，完成定向检查和前端推送前检查后提 PR，CI 全过 squash 合并，保留 wmj；不部署。

参考：MDN Using Web Workers（消息复制与 ArrayBuffer transfer）；PostgreSQL 18 Explicit Locking（行锁与事务并发）。

## 测量与调整

一次性传回完整对象的初版在受控 5 万条 compact 清单中产生约 43 ms 主线程间隙，比直接展开的约 24–29 ms 更差，故删除该路径，改成 256 项逐批确认。20 万条/约 7.98 MB 清单的两轮内置浏览器对照中，直接解码展开约 110–123 ms，主线程间隙约 110–124 ms；分批 Worker 总耗时约 555–562 ms，最大响应间隙约 11–24 ms。结果支持响应性改善，不支持总耗时提速。小于 1 MiB 的清单保留直接路径。此为受控传输数据，不是真实公司图纸性能指标。

## 交付验证

13 项 Node 与 55 项服务/真实 PostgreSQL 定向测试通过；前后端类型检查、前端构建、发布身份检查通过。受控 DXF 1202 实体在内置浏览器完整显示，确认 Worker、首帧及可交互诊断。迁移 0081 回填和并发保护已测试；存储删除使用替身验证，未连接生产服务或进行真实对象存储/原生引擎端到端联调。
