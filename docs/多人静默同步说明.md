## 方案依据

本次比较了定时轮询、SSE 失效提示、WebSocket 三种方式。项目已具备通知 SSE 端点和 PostgreSQL LISTEN/NOTIFY 桥，业务修改仍通过 HTTP 写接口完成，因此选择复用 SSE，只提示哪些资源需要重新读取。

| 方式 | 本次场景的收益 | 代价与取舍 |
| --- | --- | --- |
| 定时轮询 | 实现简单，漏事件也能恢复 | 短周期空读较多，长周期更新延迟较大；本次保留 30s 补取作为兜底 |
| SSE 提示 + 鉴权读接口 | 适合服务端单向提示，可复用现有连接和跨实例广播 | 事件可能丢失，需重连及周期补取；本次采用 |
| WebSocket | 可双向交换消息 | 需要额外协议和连接管理；目前没有协同光标、字符级共同编辑等需求 |

调研采用官方资料：

- [MDN：使用 Server-sent events](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events/Using_server-sent_events)：命名事件、EventSource 自动重连及连接限制。应用每次登录只建立一条连接；HTTP/1 的同源连接限制仍适用于同一浏览器打开多个标签页。
- [MDN：Page Visibility API](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)：隐藏页面暂停自动取数，回到前台后补取。
- [MDN：WebSocket API](https://developer.mozilla.org/en-US/docs/Web/API/WebSockets_API)：双向消息能力，用于比较方案。
- [React：Render and Commit](https://react.dev/learn/render-and-commit)及[保留和重置状态](https://react.dev/learn/preserving-and-resetting-state)：保持组件位置和业务键，避免因自动更新重建编辑器。
- [PostgreSQL：NOTIFY](https://www.postgresql.org/docs/current/sql-notify.html)：通知桥适合失效提示；数据库状态仍以正常读接口为准。

## 使用体验与覆盖

现有7类路由全部接入：地图、项目空间、项目详情六视图及日报四子视图、九阶段模板、工作台任务/问题/我的计划、操作记录、文件库两栏。新增/删除/退出可见集合由相应资源失效后回读收敛；并非每个按钮各开一条连接。界面和操作链路清单见[完整清单与计划](多人静默同步界面清单与补齐计划.md)。

别人保存后，当前画面局部更新，不重导航、不整页reload、不切加载骨架、不逐事件弹Toast。保留已有行/卡片顺序、路由、查询、分类、折叠和输入；新增追加，删除移除。普通回读保存纵横滚动及可见锚点；甘特范围变动保留可见日期。实体跨负责人/状态分组会真实归组；整组删除或内容高度不足时按实际范围钳制，不能承诺结构性删除永远0px变化。

输入、编辑弹窗、确认、拖动、本地写入期间暂缓普通应用；异步读取期间开始编辑或写入也丢弃结果再排队。只读预览、变更详情、审计及任务附件/历史可独立补读，保持窗口和浏览状态。随行文件下拉从父读面更新，上传队列/删除确认仍以对象身份保留。已打开预览维持本次URL/历史版本，不重建 PDF.js / 图片 / ONLYOFFICE 查看器；CAD 当前只保留暂不可预览提示，未来独立 ViewerSession 接入后同样保留本窗口状态；失效的是后续预览签名和缩略图缓存。

## 草稿和冲突

- 项目编辑及归档沿用打开时版本。409保留全部字段，读取最新内容供核对，只有明确确认后再按该版本提交；新一轮外部修改仍会409。
- 任务抽屉即时保存串行，只有自己的成功响应推进基线；保存期间继续输入会保留新文字，失败不显示“已保存”。核对最新任务后显式重试；仅显式改动经理名单才回写项目，普通任务保存不回写旧经理；项目经理写失败不能伪报整次成功。
- 日报暂存绑定draftId/version，外部更新提示而不替换输入。草稿被删后不能退回POST默默复活；可显式选择“保留当前内容，另建日报”。
- 脏模板保留内容和旧version，当前/缓存阶段失效；添加任务候选独立更新，确认时核对节点/模板仍存在。已生成任务保留生成快照。
- 已确认403/404收敛相关旧数据及写入口。干系人按最新投影隐藏失权字段，保留可编辑草稿，仅提交仍有权的改动键；既有干系人接口无version，本次不新增其乐观锁。

## 本人偏好与审计

偏好PATCH在账号行锁事务内合并，首次插入也纳入锁保护；不同键并发更新保留彼此提交值。`prefs._revisions`是内部元数据，GET公开`revisions`；更新`myPlanBoard`或`homeSavedFilters`必须传对应`expectedRevisions`，缺失400、过期409。禁止客户端改内部版本。便签保留失败草稿，编辑窗口内可核对整板并明确确认重试，也可采用远端内容。保存请求期间新输入不会因成功关窗而丢失。

本人偏好在事务内发定向提示，接收者是本人各连接；不同账号不收到preferences提示。列显隐/背景档位/卡片水印/界面语言/常用筛选同步已保存配置；醒目模式沿用主干Push 290下架口径，不恢复前端读写，不切换当前URL条件；工作台展开记忆保存但不接管当前浏览展开状态。**前后端/契约需同批发布**：旧客户端集合写入缺版本会被400拒绝，应重新打开应用加载新客户端。

审计实际INSERT后在相同连接/事务发audit类别提示，PG事务提交后交付；覆盖下载GET、独立拒绝留痕及后台调用审计仓储的写入。历史回读以`beforeId/windowId`固定窗口，新增日志不推动当前历史页；前台第一屏读最新。显式筛选/换页建立新窗口。该窗口防普通后续新增漂移，不是数据库长期可重复读快照。

## 通道与请求节奏

1. 共享HTTP写成功后按路由标记资源并尽力发布；普通读、失败写、分片传输不发业务提示。实际审计与个人偏好分别从写事务发提示。
2. 发布及接收端250ms合并资源，PG `notify_stream`跨实例传播；接收按recipient隔离，同一用户多个连接共用一次合并帧。
3. SSE `invalidate`载荷仅resources：projects/tasks/reports/issues/files/stakeholders/templates/dicts/users/audit/permissions/preferences。无记录id、业务字段或个人内容；各接口仍鉴权。
4. 每个订阅读面至少间隔1s、单飞。持续事件合并为后续批次，慢回填不被父列表反复取消。全应用读请求最多6路；相同默认GET共享在途响应，写前后清除复用入口，写后补读不复用写前结果。
5. 项目/任务/日报/联系人/目录和文件集合逐200条读取，超过20,000条报范围错误，避免只显示首200条或首20页而不告知。各分页请求使用原有排序；持续修改下不构成跨所有分页的事务快照。
6. 隐藏页暂缓；SSE打开/重连、回前台、网络恢复补取，另有30s补偿。网络失败保留当前画面，后续重试；401沿用登录。
7. 人员/组织/权限变化触发统一权限画像更新和服务端画像缓存失效；仍沿用既有权限开关与逐请求鉴权，角色外部调整无即时事件时由周期读取收敛。

无新增表、迁移、权限位或依赖。事件不承担业务状态/Outbox的可靠投递职责。SSE同浏览器多标签仍受部署HTTP连接配置与既有每账号连接上限约束；十个不同用户不等同于十个同账号标签。
