# 项目总结功能设计与验收（2026-10-27）

> 范围：LibiaoLink 中**某个业务项目**的阶段性项目总结，入口在项目空间卡片的「导出项目」右侧星芒按钮。本文不是 LibiaoLink 平台自身的开发复盘，不涉及正式机 `10.1.103.44`。

## 1. 结论：脚本定事实，AI 只写叙述，人工确认发布

采用混合方案，而不是让 AI 直接读取数据库后自由总结：

1. **脚本事实层**：服务端按固定规则读取项目、阶段、任务、日报、问题、文件、变更，生成带数据截止时间的不可变事实包。
2. **AI 叙述层**：只把结构化事实包交给 OpenAI 兼容通道，要求输出六段 JSON 叙述；不得出现阿拉伯数字，不得复述或重算统计，只能依据脚本已定稿的 facts 作定性概述，不得改写解决状态、缺件或验收结论。
3. **规则兜底**：AI 配置缺失、超时、HTTP 失败、JSON / 字段校验失败、数字越界或与脚本结论冲突时，整次回退规则模板；模板同样只作定性描述，不重复统计数字，仍可生成可编辑草稿。
4. **人工确认**：项目经理或系统管理员（且项目部门权限为 `edit`）审核并修改叙述，保存草稿后确认发布；确认版才是正式总结。

不采用：

- **纯 AI 汇总**：统计数字、问题是否解决、成果是否齐全容易出现不稳定和幻觉，也无法满足可追溯要求。
- **纯脚本成文**：事实可靠，但六段长文可读性差，且项目经理仍需大量手工润色。
- **前端计算**：数据来自多个分页接口，前端聚合会放大口径漂移和权限绕过风险。

## 2. 用户流程

1. 项目空间卡片点击星芒 → `GET /projects/{id}/project-summaries/latest`。
2. 从未生成：有权限者看到「生成项目总结」，只读成员看到需项目经理生成的说明。
3. 生成：脚本并行读取六类证据；事实包定稿后调用 AI，AI 成功后返回叙述，失败则规则模板接管。
4. 草稿：展示完整事实包与六段可编辑叙述；可保存草稿、按最新数据重新汇总。
5. 确认：二次确认后保存未落库修改，再调用确认接口；旧 confirmed 与其余草稿转 superseded，新版本成为唯一 confirmed。若保存成功但确认失败，界面保留已保存内容与新版本号，不把用户退回到旧草稿状态。
6. 已确认：弹窗只读，可复制、打印 / 另存 PDF；数据更新后可重新生成新草稿。
7. 读取：项目可见成员均可打开最近总结；生成 / 编辑 / 确认按钮由服务端 `canEdit` 与草稿状态共同决定。

## 3. 事实与规则

### 3.1 数据来源与截止时间

- 项目主数据、阶段、任务、日报、问题、项目文件、变更记录。
- 所有分页读取最多 20,000 条 / 类；超出返回业务错误，不静默截断统计。
- `dataCutoff` = 本次汇总开始时间；事实包保留读取证据条数。
- 阶段最多 50 条、时间线最多 200 条、问题与待整改分别最多 500 条；超出时统计仍按全量计算，并在数据质量提醒中明示。

### 3.2 问题是否解决

- `resolved`：状态 `done`，且解决方案非空、`closedAt` 非空。
- `needs_evidence`：状态 `done`，但解决方案或关闭记录缺一项。
- `unresolved`：`open` 或 `in_progress`。
- 建议接手人：问题责任人 → 责任部门 → 项目经理（姓名缺失时使用部门兜底文案）。

### 3.3 遗漏 / 待整改

- 未解决问题、问题关闭证据缺失。
- 未完成且逾期、未完成且未分配负责人。
- 任务要求成果类型没有对应任务文件且文件状态不属于 final / changed / archived。
- 项目状态 done / archived，但仍存在未完成任务、未解决问题或成果缺件。
- 创建超过 30 天的 active / paused 项目无日报，或最近日报超过 30 天。
- 项目无阶段、无任务等基础数据缺失。
- 按高 / 中 / 低风险分级，按建议接手人归组；该结果不等于正式任务分派。

### 3.4 统计

任务总数 / 完成 / 进行 / 待开始 / 逾期 / 未分配；日报总数 / 草稿 / 提交 / 补填 / 最近日期；问题总数 / 已解决 / 未解决 / 处理中 / 关闭证据缺失；文件与变更总数；成果要求 / 已定档 / 缺件；阶段总数 / 完成 / 进行。全部由脚本计算。

## 4. AI 安全与输出约束

- 输入只含事实包的必要字段；问题与变更字符串明确标注为数据，不作为指令。
- 输出必须是恰好六字段 JSON，每段 1~1500 汉字；服务端再按 1~4000 字符契约校验。规则模板与 AI 叙述都只作定性描述，统计数字仅在 facts 事实区展示。
- **禁止出现阿拉伯数字**：统计和日期由事实表独立展示，避免模型把不同指标的数字错配。
- 冲突校验：仍有未解决问题时不得说「全部解决 / 无遗留」；仍有证据缺失时不得说记录完整；仍有成果缺件时不得说齐全；仍有未完成任务时不得说全部完成；有整改项时不得说无风险。
- 任何一个校验失败都整次回退模板，不混用 AI / 模板段落。
- AI 失败原因写入 `fallbackReason` 并在弹窗中展示，便于判断本轮质量。
- 复用现有 `TRANSLATE_API_*` 兼容通道是本次的部署便利选择；若后续需要独立模型、额度或审计，可替换 AI 服务而不改事实包、数据库和前端契约。

## 5. 权限、状态与审计

- 读取：`project.view`，项目可见成员。
- 生成 / 保存 / 确认：`project.update`，且服务层强校验「项目经理或系统管理员」+ 当前项目部门权限 `edit`。
- 草稿保存和确认使用 `version` 乐观锁；并发修改返回 409。
- 同项目同时最多一条 confirmed；确认时旧 confirmed 与其余草稿转 superseded，旧版确认人 / 时间保留，审计与历史版本仍可追溯。
- 生成、保存叙述、确认均写 `project_summary` 审计：生成记录引擎 / 模型 / fallback / 统计；编辑记录六段字段级 before / after；确认记录数据截止与关键风险数。
- 已确认版本不可直接编辑；修订必须重新生成草稿。

## 6. 数据与接口

- 迁移：`database/migrations/0076_project_summaries.sql`。
- 契约：`shared/src/modules/project-summaries.ts`；OpenAPI 四条路径；审计对象类型新增 `project_summary`。
- 服务端：`server/src/modules/project-summary/`，领域模块 `project-summary`。

- 接口：
  - `GET /api/v1/projects/{id}/project-summaries/latest`
  - `POST /api/v1/projects/{id}/project-summaries`
  - `PATCH /api/v1/projects/{id}/project-summaries/{summaryId}`
  - `POST /api/v1/projects/{id}/project-summaries/{summaryId}/confirm`

## 7. 界面验收点

- 星芒按钮位于导出右侧、删除左侧；悬停 / 键盘聚焦出现，点击不冒泡进入项目详情。
- 弹窗展示数据截止、生成 / 确认信息、引擎与 fallback、证据条数。
- 六段叙述在草稿且有权限时可编辑；只读成员与已确认版本显示文本。
- 统计、阶段、时间线、逐条问题结论、风险分级待整改、按人接手事项、数据质量提醒均可见。
- 保存、确认、重新生成、复制、打印可用；失败有可见错误，不静默失败。
- 未保存修改关闭时二次确认；Esc / 焦点陷阱 / 背景滚动锁与现有弹窗一致。
- 打印只输出总结正文；四语界面文案完整。

## 8. 非目标与已知限制

- 不做自动验收、质量合格判定或替代项目经理签字。
- 不跨项目合并总结，不生成公司级经营分析。
- 不自动创建整改任务、不自动通知接手人；当前只给建议接手人与动作。
- 事实质量依赖源数据完整性；缺数据会进入「数据口径提醒」和「基础数据缺失」，不会被 AI 掩盖。
- 不修改历史源数据，无存量回填。
- 本次不接触正式服务器；发布验证只在测试机 `10.1.104.44 / test-pm.libiaorobot.com` 进行。
