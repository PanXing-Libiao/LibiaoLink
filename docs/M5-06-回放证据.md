### 口径登记

1. **无新迁移**：2B 复用 `0061` 的 `notify_delivery_messages` / `notify_deliveries.message_id` / `resend_of_message_id`，不扩展表结构；这是前置 2A 的收口读面与写面。
2. **重发不直连渠道**：重发只写新 outbox（topic / payload 沿用原消息），由既有 worker 消费者继续执行 C5-04 降级、限速、每日上限与渠道保障；不在 API 进程直接发外部消息。
3. **幂等顺序**：事务内先按 `source_dedupe_key` 读既有重发归档；命中即返回，再读取原消息并做 failed / dead 门禁。这样原消息在首次重发后被消费推进，也不会让同 key 重试变成 409。
4. **权限口径（Push 274 定案）**：功能权限缺失按全仓既有 `PermissionService.assertCan` 返回 403 `FORBIDDEN`，且判定先于资源探测；功能权限通过后，记录不存在或记录级不可见（项目 / 收件人范围、已软删等）返回 404 `NOT_FOUND`。S8-4 第三节“无权与不存在统一按 404”仅指记录级，不适用于功能权限；本次不改守卫与实现，仅澄清契约文案。
5. **掩码边界**：读面只返回 `targetMasked`（末 4 位）与脱敏后的错误；不返回完整 target、payload、metadata 或 Idempotency-Key 原文。审计与重发归档 metadata 只记哈希 / 来源 id。
6. **失败重试**：同一 key 的并发请求以唯一 `source_dedupe_key` 收敛；归档与 outbox / 审计同事务，任一步失败整体回滚，不留下半条重发链路。
