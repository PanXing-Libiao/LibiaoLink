## 1. 目标与处理原则

目标是让团队对常见二维 DWG 获得**可用、可解释的预览**：主体可识别，影响判断的遗漏清楚，原件始终可下载。这里的预览不作为加工、尺寸或工程验收依据。

以实际业务影响和证据决定工作量：

1. **必须处理**：实际图纸中主体、重要文字/标注、关键外参或布局缺失、错位、遮罩错误，会让用户误判或无法完成看图；修复到约定范围，暂时不能修时明确该范围不可用，并保留原件下载。
2. **可说明后使用**：文字可读但字体形状略有差异、抗锯齿或非关键外观差异；在标准说明中写清近似，不要求逐像素一致。
3. **暂不承诺**：无实际业务需求或无足够证据的三维编辑、专有对象求解、完整 ACIS 内核、任意动态块重算等；保留源对象与损失，不伪装为支持。
4. **条件升级**：最初看似小的偏差若影响识字、尺寸含义、遮挡关系或业务决策，按必须处理项重排。未知影响先登记“待确认”，不默认无影响。
5. 不为少量没有业务影响的差异反复补丁、造框架或进行全量审计。复用现有资源、裁剪、查看器与诊断能力；只为当前缺口增加必要实现和定向检查。

“显示部分内容”不是“已验证完整”。已有入口状态、作业状态和 UCD 的 `partial` 各有含义，实施时沿用各自契约，不把入口可用写成整图完整。

## 3. 社区参考及使用边界

- [ACadSharp](https://github.com/DomCR/ACadSharp/blob/760bd909c384b8f1a47c29acd1777ea8e3fe7cfe/README.md)：当前固定依赖为 3.8.30、提交 `760bd909c384b8f1a47c29acd1777ea8e3fe7cfe`；优先检查该版本已有的对象、视口和显示数据，再按缺口选择性适配。读取成功不等于显示语义完成，不为个别样例直接升级依赖。
- [truedxf](https://github.com/tth05/truedxf)：其统一显示列表、字体、裁剪及按能力对照原 CAD 的方法值得借鉴；它是 DXF 项目，不读取 DWG。仓库已有部分规则的固定版本与许可记录，应先核实现有代码可否经格式无关接口复用；不能把 DXF 对象或未经核验字段直接冒充 DWG 结果。
- [ezdxf drawing](https://ezdxf.readthedocs.io/en/stable/addons/drawing.html)：前端解析显示语义、后端负责画图，并公开文字、三维和视口等限制；可参考这种清晰边界，不将它的结果外推为 DWG 支持。

## 4. 实施顺序

### 阶段 A：建立可用基线和标准说明

1. wmj 使用已有正式大图、公开样本和现有记录，对照原 CAD 选少量代表区域：主体、中文/换行、尺寸文字、引线及块属性。记录源版本、区域、是否影响理解和现有损失；正式图继续私有保存。
2. 在现有能力/损失记录中按“已验证、可用但近似、部分/缺失、未验证”标记实际结果，不建立独立报表系统；不能根据未显示对象数量推算全图百分比。
3. 给模型预览制定简短标准说明，例如：“当前为二维部分预览；缺少原字体或配套资源、未支持对象可能影响显示，必要时请下载原文件查看。”已有明确损失的图纸补充具体类型；不能只显示统一说明而掩盖重要内容缺失。
4. 输出一份经过实际图核对的待办：必须修、说明即可、暂不做。公开样本 3 个空布局登记为真实缺口，但是否纳入首批由实际布局使用决定。

完成条件：两份现有样本的范围及损失可解释；关键缺失不会被标为完整；不需要新增通用诊断平台。

### 阶段 B：先解决实际影响看图的问题

按阶段 A 判定逐项完成，不把所有源类型列为必修：

1. **主体与遮挡**：优先处理实际出现且影响看图的基础图元、块/属性错位和 WIPEOUT；优先使用源保存图形或已验证的公共能力。不能可靠还原时明确局部缺失，保留下载。
2. **常用文字**：验证中文、普通 TEXT/MTEXT、常用尺寸文字与替代字体的可读性。可读的小外观差异标准说明即可；如关键文字不可读，按实际字体请求选择性接通现有已验证字体资源能力，缺字仍明确标记。竖排、分栏和复杂富文本只在实际需要时扩展。
3. **关键标注和代理**：先定位真实图中的引线箭头及代理对象；有源保存图形则优先使用。仅对影响识图的原语或样式做选择性适配；未支持的专有求解继续说明。
4. **普通填充**：针对实际使用的实心、基础图案与孔洞做代表性对照。渐变或特殊岛屿规则若不影响业务，保留限制说明；若会误填或遮挡主体，再按具体类型修复。

每项完成条件：受影响源对象及身份可追溯；正常、缺失/近似结果与原图或可靠样例一致；已有普通/保留实例路径在该范围内显示与拾取一致。无法确认正确的范围保持部分支持，不扩大声明。

### 阶段 C：按业务触发的布局与配套能力

- **布局视口**：如果首批场景需要布局，先只接二维俯视、矩形视口的源中心、比例、方向及图层可见性；使用已有纸面/模型投影与裁剪契约。选公开含视口样本及实际业务布局对照；不同规模路径复用同一语义。非矩形、透视、倾斜或三维视口仅在有需求且有证据时扩展，否则明确不支持。没有布局业务需求时，维持说明与原件下载。
- **字体/外参/图片/PDF**：当实际文件依赖它们并影响看图时，先列出原始引用和缺失项，通过已绑定文件版本、权限与摘要提供所需资源；再选择性复用现有解析/裁剪能力。缺失资源不猜同名或读取图纸指定的任意路径。无业务需求的底图格式不预先接入。
- 阶段完成条件：只对已验证组合宣称支持，缺失配套、未支持视口及近似有清楚说明；相关图纸仍可下载原件。

### 阶段 D：平台接入和目标环境验收

仅当上述首批约定范围满足后，wmj 与 lan、px 对齐，沿用现有平台链路完成：

1. 文件版本、原 DWG SHA 和按需配套版本绑定；明确来源、窗口与逐请求权限。
2. 在已有任务/沙箱中接入固定原生读取器与 UCD，处理排队、取消、失败、部分结果与资源租约；不把成功空图或未校验产物发布为完整结果。DXF 部分结果规则不能自动当作 DWG 已支持。
3. 为 DWG 建立覆盖读取器、映射规则与必要资源的版本/缓存身份；评估现有版本拆分与旧产物兼容，涉及契约/迁移按归属评审。
4. 在目标 Linux 沙箱按实际负载验证读取、组装、产物大小、浏览器首开/交互及取消；结合整机内存确定资源档位。现有 2 GiB RSS 与该真实大图不兼容；不直接把一次 2.5 GiB 实验当作已批准的生产配置。
5. 公司测试环境用真实账号和经授权图纸核验打开、提示、图层、拾取/定位及下载。只有这些结果实际完成，才能更新开放状态；生产部署状态另行记录。

## 5. 验证与完成标准

- 使用已有真实大图和公开样本，不另建庞大样本库；每个新增支持点只补能证明该行为和失败边界的定向用例。需要比较原 CAD 时，检查主体、关键文字、位置和遮挡即可；没有业务影响的抗锯齿差异不追求逐像素一致。
- 每项记录：使用文件/版本、能力、实际状态、证据、是否影响看图、处理方式。未运行、未验证和部分支持明确区分；同一份记录沿用现有能力矩阵及交接文档。
- 首批模型预览完成的条件：约定业务图的主体及关键文字/标注可识别；重要缺失、替代字体和未支持资源清楚；图层、定位和原件下载可用；未支持布局不伪装为空白成功；资源约束下不发布未校验产物。
- “首批可用”只针对已验收图纸与能力，不代表全部 DWG、所有字体/视口/代理对象或工程精度。未发生实际业务需求的边缘能力可以持续记录，不作为无止境的补齐清单。
- 验证只跑改动相关的定向检查；本计划是纯文档，不运行全量构建。实施或推送时继续遵循用户的验证限制及仓库适用门禁；如两者不能同时满足，应如实报告，不能写成已通过。

## 6. 暂缓清单与升级触发

默认仅说明、不列入首批：三维编辑与求解、完整 ACIS/专有对象解释、动态块参数重算、全部字体的像素级一致、透视/三维视口、罕见底图及打印设备效果。

以下情况升级为实施任务：真实业务图的主体或标注无法辨认；遮罩/填充错误改变图意；团队实际需要的布局空白；必要配套缺失无法补齐；目标环境无法在既定资源内完成任务。升级时明确具体图纸、受影响对象和结果，再选现有实现或有证据的社区方法。
