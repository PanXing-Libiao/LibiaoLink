## 怎么验的（不是看截图就算数）

- **人话护栏是断言出来的**：页面文本整体扫 `/api/`（零命中）与 36 位 UUID 正则（零命中）—— 一屏任意一行把路由 / 内部 id 露出来就变红（这正是 2026-10-09 的业务原话要求）。
- **计数对账对的是库**：页面右上「共 N 条」逐次与 PostgreSQL 直查对账 —— 总 7706 / 修改 1016 / 越权拒绝 262 / 潘兴 ∩ 越权拒绝 200 / 今日 ∩ 潘兴 ∩ 越权拒绝 0（2026-10-09 上午，当天尚无新留痕）。三轮脚本修正的正是两处对账口径（结果筛仍叠加时的交集、时间筛与库内交集对账 + 空态分支），页面代码没改。
- **请求串逐条断言**：首屏只允许 `page` / `limit`；筛选后必须出现 `action=update` / `actorId=<uuid>` / `result=denied` / `from` / `to`，时间端点按 Asia/Shanghai 当日换算成 ISO —— 地址栏、请求、页面三者同源（地址即状态）。
- **空集是有效用例**：`action=update ∩ result=denied` 在库内为空 → 页面必须出空态而不是错误；越权尝试（`result=denied`）在结果列一眼可见（C7-03）。
- **菜单位置是量的**：「操作记录」与「退出登录」同属一个菜单容器（`role=menuitem` 两枚）、纵向相邻（top 差在按钮高度内），不是按截图顺序目测。
- **零残留**：本页只读；唯一写操作是脚本自建的临时会话，跑完 `revoked_at` 置位并复查 `revoked_at is null` 计数 = 0。
