## 1. 已定决策

1. 「分别下载」与「打包下载 ZIP」都保留，两者不是互斥替代关系。
2. 独立下载失败或疑似被浏览器拦截时，必须能立即改用 ZIP；ZIP 入口在筛选栏批量操作组中常驻，不依赖前端识别浏览器拦截。
3. 浏览器没有可靠的“多文件下载被拦截”网页回调，因此不得声称能够自动检测拦截。独立下载结束后统一提示“如有文件未下载或浏览器提示已阻止，请改用 ZIP”。
4. 不使用“超过某个数量就自动改 ZIP”的规则。浏览器行为与触发频率、站点策略和用户授权有关，不按文件数量做硬阈值。
5. ZIP 必须由服务端生成，浏览器只下载一个签名地址；不得把所有源文件逐个下载到浏览器后再在 Web 端压缩。
6. ZIP 采用“全有或全无”：任一选中文件或版本校验失败、对象读取失败、超限或写包失败时，整批失败，不生成缺件包。
7. 单个文件下载、预览、变更前 / 变更后版本语义、现有审计口径不得因本功能改变。
8. 客户端断开时停止 ZIP 流式生成，清理本机临时目录；已上传对象立即 best-effort 删除，并保留 TTL 到期清理任务兜底。

## 2. 浏览器实测证据

### 2.1 测试环境

- 浏览器：Microsoft Edge `157.0.4341.42`。
- 系统：Windows。
- 下载对象：跨源短时签名附件。
- 下载方式：与现有 `triggerDownload` 同口径，`fetch` 取得签名地址后通过 `<a download>` 触发。
- 站点多文件下载权限：保持浏览器默认的“自动下载多个文件时询问”，未添加站点放行规则。

### 2.2 结果

| 每次触发间隔 | 文件数 | 实际成功数 | 结论 |
|---:|---:|---:|---|
| 0 ms | 2 | 1 | 连续触发会丢失前序下载 |
| 0 ms | 3 | 1 | 不是固定数量拦截，而是触发过快 |
| 500 ms | 2 | 2 | 全部成功 |
| 500 ms | 11 | 11 | 全部成功 |
| 50 ms | 20 | 20 | 全部成功 |
| 100 ms | 30 | 30 | 全部成功 |
| 100 ms | 50 | 50 | 全部成功 |

结论：

- 当前实测没有发现“超过固定数量就拦截”的阈值；50 个文件在合理间隔下仍可全部发起。
- 不能把 50 当作浏览器安全阈值。50 只是本方案主动设置的业务上限。
- 页面无法可靠获知浏览器是否拒绝多下载授权，也无法获知某个 `<a download>` 是否最终落盘。
- 因此前端只能确认“已发起”，不能确认“已下载成功”；ZIP 兜底入口必须始终可见。
- 测试产生的临时下载文件与临时浏览器目录已清理，未保留测试残留。

## 3. 前端交互方案

### 3.1 入口与布局

- 在 `frontend/src/components/ProjectFilesPanel.tsx` 现有筛选栏的最右侧增加「批量下载」按钮；按钮与筛选栏同一行，右对齐到表格“操作”列上方，不放入 `thead`。移动端允许控件换行，但入口仍在筛选栏内。
- 点击「批量下载」进入批量选择模式：表格出现选择列，筛选栏右侧切换为批量操作组（已选数量、当前页全选、清空选择、分别下载、打包下载 ZIP、退出批量）。
- 未进入批量模式时不显示复选框，避免改变普通浏览与单行下载的既有交互。
- 表格第一列增加行复选框；现有“文件名”列、整行点击预览、操作列下载按钮保持原位置。
- 筛选栏批量操作组包含：`已选 N 项`、`当前页全选`、`清空选择`、`分别下载`、`打包下载 ZIP`、`退出批量`。
- 未选中任何文件时，两个下载按钮禁用；超过 50 项时不得静默截断，应提示缩小选择。

### 3.2 选择状态

- 使用行级 `Set<rowKey>` 保存选择，不能只用 `fileId`；同一文件的“变更前 / 变更后”必须可分别选择。
- 普通文件行以 `currentVersionId` 判定可下载；变更前 / 变更后行以行级 `versionId` 判定；没有可解析版本的行不可勾选。
- 行键去重后仍按 `(fileId, versionId)` 去重；完全相同版本只下载 / 打包一次。
- 当前页全选只选择当前页可下载行；表头复选框支持全选、全不选和 `indeterminate` 半选态。
- 允许跨页保留选择，但总选择数不得超过 50。
- 切换项目或修改关键字、阶段、状态筛选时清空选择，避免批量操作命中不可见行。
- 实时刷新或删除后，自动剔除已不存在、已回收或版本不可用的行。

### 3.3 分别下载

- 按选择顺序串行处理，不并发预取全部签名地址。
- 每一项依次执行：`fetchDownloadUrl(fileId, versionId)` → `triggerDownload(url, fileName)` → 等待约 150 ms。
- 150 ms 是实测后的保守值；若后续在正式环境复测发现仍有点击丢失，可调整常量并在本文件登记。
- 下载过程中显示 `i / n` 进度和正在处理的文件名，并禁用重复提交。
- 单项签名失败不应中断其余项；记录失败项并继续，结束后汇总“已发起 N 项、签名失败 M 项”。
- 无论是否出现错误，结束后都显示持久兜底提示：`已发起 N 个文件的下载。若浏览器提示已阻止或只收到部分文件，请改用“打包下载 ZIP”。`
- 文案必须使用“已发起”而不是“已下载成功”，不得暗示页面已确认落盘。
- ZIP 按钮在筛选栏批量操作组继续常驻，用户不需要重新选择文件。

### 3.4 打包下载 ZIP

- 点击后显示不可误关闭的打包进度遮罩，文案包含选中文件数量，例如“正在打包 N 个文件…”。
- 前端调用归档接口并等待服务端生成完成；成功后取得短时签名地址，用现有 `triggerDownload` 触发单个下载。
- 整个 ZIP 只占一次浏览器下载，不依赖浏览器“多文件下载”授权。
- 接口失败时显示服务端可读错误，并保留“分别下载”和“重试 ZIP”入口。
- 前端不得自行压缩、拼接 Blob 或读取源文件内容。

### 3.5 文案与国际化

- 所有新增文案同步中、英、日、韩四套文案。
- 新增文案至少包括：已选数量、全选、清空、分别下载、打包下载、打包中、ZIP 生成失败、ZIP 兜底提示和 50 项上限提示；200 MB / 2 GB 超限直接展示服务端可读错误。
- 复选框、表头全选和进度状态必须提供 `aria-label` 或等价可访问名称。

## 4. 共享契约

契约唯一来源为 `shared/src/modules/files.ts`；以下命名与字段已按当前实现落地，生成物已重新生成，待 wmj 评审确认。

```ts
export const FileArchiveItemSchema = z.object({
  fileId: UuidSchema,
  versionId: UuidSchema,
  /** 仅用于 ZIP 内显示名；服务端清洗，不参与鉴权，并强制使用该版本真实扩展名。 */
  entryName: z.string().min(1).max(255).optional(),
});

export const FileArchiveRequestSchema = z.object({
  items: z.array(FileArchiveItemSchema).min(1).max(50),
});

export const FileArchiveResponseSchema = z.object({
  batchId: UuidSchema,
  fileName: z.string(),
  url: z.string(),
  sizeBytes: z.number().int().min(0),
  expiresAt: DateTimeSchema,
  itemCount: z.number().int().min(1).max(50),
});
```

接口：

```text
POST /api/v1/projects/{id}/files/download-archive
Content-Type: application/json

{ "items": [{ "fileId": "...", "versionId": "...", "entryName": "可选显示名" }] }

200 OK
{ "batchId": "...", "fileName": "...", "url": "...", "sizeBytes": 123, "expiresAt": "...", "itemCount": 2 }
```

路由归属：

- 挂在 `FileLibraryController` 所在的项目域控制器下。
- 守卫顺序：`SessionGuard` → `CsrfGuard` → `ProjectAccessGuard`。
- 路由要求 `file.download`；在记录级可见性之后判定，避免通过权限错误泄露项目或文件存在性。

## 5. 服务端设计

### 5.1 模块与代码边界

- 将 `server/src/modules/project-export/project-export.archive.ts` 中的 `ProjectZipWriter` 抽到公共基础设施目录，例如 `server/src/common/zip/`。
- `project-export.archive.ts` 改为引用公共 writer，并可保留兼容导出，避免项目导出行为变化。
- file 模块新增归档服务，例如 `FileArchiveService`；不得从 file 模块反向依赖 project-export。
- 路由实现放项目文件控制器，业务校验、ZIP 生成、临时对象和审计放归档服务。

### 5.2 生成链路

1. 校验请求条数；按 `(fileId, versionId)` 去重并保持首次选择顺序。
2. 校验项目可见性与 `file.download` 权限。
3. 获取同账号 advisory lock；已有打包任务时返回 429 `RATE_LIMITED`。
4. 批量读取文件与版本，逐项校验文件属于路径项目、文件未回收、版本属于该文件；计算并校验单文件不超过 200 MB、解压后总量不超过 2 GB。
5. 在系统临时目录创建 `0700` 权限的目录与 ZIP 临时文件。
6. 按用户选择顺序逐项读取对象存储流并写入 ZIP；任一读取、大小 / 哈希校验或写入失败整批失败，stream 受请求断开与 4 分钟超时信号控制。
7. ZIP 写完后流式上传到对象存储临时前缀 `temp/file-archives/{batchId}.zip`。
8. 通过 `ObjectStorage.signDownloadUrl` 签发 `application/zip` 下载地址，`Content-Disposition` 使用归档文件名；随后写入一次性清理任务。
9. 在同一数据库事务中逐文件写下载审计，审计成功后才返回 JSON；前端再触发签名地址下载。
10. 任一阶段失败时删除已上传临时对象并清理本机临时目录；客户端断开时中止生成和后续步骤。

禁止项：

- 禁止在 API 内存中拼接完整 ZIP。
- 禁止在浏览器端 fetch 完整 ZIP 成 Blob 后落盘。
- 禁止部分成功时返回缺件 ZIP 且不告知用户。
- 禁止把对象键、服务器绝对路径、内部存储异常原样返回前端。

### 5.3 ZIP 条目命名

- 基础文件名使用 `versionFileName(file.name, version.objectKey)`，确保扩展名与所下载版本真实对象一致。
- 前端传入的 `entryName` 仅作为显示名输入；服务端必须：
  - 去除 `/`、`\`、控制字符、首尾点和尾随空格；
  - 拒绝空名和路径穿越；
  - 限制长度；
  - 强制替换为该版本对象对应的真实扩展名；
  - 对同名条目追加 `_2`、`_3`，扩展名保持在末尾。
- 建议所有条目放在以项目编号和名称命名的根目录下，例如 `[项目编号] 项目名称_项目文件/`。
- 变更前 / 变更后可由前端传入带侧别标签的 `entryName`；服务端仍按上述规则清洗和去重。
- 同一 `fileId` 的不同版本必须允许同时入包并各自保留扩展名与侧别名称。

### 5.4 临时对象与过期清理

- ZIP 临时对象不得长期保留。
- 下载签名窗口沿用 `S3_DOWNLOAD_URL_TTL_SECONDS`。
- 临时对象清理时间应晚于签名过期时间，建议签名 TTL + 10 分钟。
- 复用现有 `jobs` 表的一次性任务能力：`cron=null`、`runAt=过期时间`、处理器调用 `purgeObject` 删除临时 ZIP。
- 若上传成功但响应失败，清理任务仍须保证对象最终删除；若任务写入失败，应主动 best-effort 清理并返回错误。
- 该方案不新增业务表、不改数据库结构；若后续改为异步任务状态机，再评估是否新增表并同步迁移与评审。

### 5.5 并发与超时

- 同一账号同时只允许一个 ZIP 打包请求；重复请求返回 `RATE_LIMITED`，避免重复占用临时磁盘和对象存储。
- 服务端生成超时默认 4 分钟，低于当前 Nginx `/api/v1` 的 300 秒读超时。
- 请求断开时通过 `AbortSignal` 中止生成并清理本地临时目录；已上传对象立即 best-effort 删除，清理任务继续兜底。
- 若真实 50 项 / 2 GB 场景经常接近或超过 4 分钟，应把本文件中的 ZIP 生成改为异步任务模型，并补充状态查询 / 轮询契约，不得直接放宽到超过网关超时。

## 6. 权限、审计与错误语义

### 6.1 权限

- 项目不可见：404 `NOT_FOUND`，不得暴露文件存在性。
- 项目可见但缺少 `file.download`：403 `FORBIDDEN`。
- 任一文件不属于路径项目、已在回收站或版本不属于该文件：整批 404 `NOT_FOUND`。
- 客户端只负责按钮可用性提示，服务端是唯一最终裁决点。

### 6.2 审计

- 独立下载继续沿用现有逐文件 `download` 审计。
- ZIP 默认按每个入包版本写一条 `download` 审计，metadata 至少包含 `versionId`、`batchId`、`archive=true`。
- 当前不另写批次汇总审计；批次可通过每文件 metadata 的 `batchId` 反查。是否增加汇总审计仍待 wmj 评审，如需增加直接修改本节和测试清单。
- 审计只记录已成功生成并签发的下载，不记录预览；日志不得包含 Secret、对象键、服务器绝对路径或文件内容。

### 6.3 错误码

- 参数为空、超过 50 项、重复项冲突或 `entryName` 非法：400 `VALIDATION_FAILED`。
- 无下载权限：403 `FORBIDDEN`。
- 文件 / 版本不存在或不属于当前项目：404 `NOT_FOUND`。
- 并发打包、限流：429 `RATE_LIMITED`。
- 超限、对象读取失败、ZIP 写入失败、上传失败或生成超时：按现有统一错误模型返回；超限默认使用 400 `VALIDATION_FAILED`，内部失败使用 500 `INTERNAL`，不得返回存储细节。

## 7. 资源上限

| 限制 | 值 | 说明 |
|---|---:|---|
| 单批版本数 | 50 | 业务上限，不是浏览器阈值；与当前表格 `PAGE_LIMIT` 对齐 |
| 单文件大小 | 200 MB | 与项目导出 ZIP 的单附件限制一致 |
| 解压后总大小 | 2 GB | 与项目导出 ZIP 的附件总量限制一致 |
| 同账号并发打包 | 1 | 防止重复生成和临时存储占用 |
| 生成超时 | 4 分钟 | 低于 Nginx `/api/v1` 的 300 秒超时 |

校验分工：

- 前端已校验单批最多 50 个唯一版本、无版本行不可选、筛选 / 项目变化清空选择；这些只用于交互体验。
- 当前项目文件列表不携带每个版本的大小，前端无法在发起前可靠判断 200 MB / 2 GB。单文件大小与解压后总量由服务端依据 `file_versions.size_bytes` 最终裁决，超限返回 `VALIDATION_FAILED` 和可读提示，前端展示服务端错误。
- 若后续需要前端提前预警大小，必须先扩展列表 / 专用检查契约下发版本大小，再修订本节；不得用文件扩展名或页面展示文本猜测。

## 9. 测试清单

### 9.1 契约与服务端

- 空数组、未知字段、非 UUID、超过 50 项拒绝。
- 重复 `(fileId, versionId)` 去重或按最终契约拒绝。
- 项目不可见返回 404，不泄露文件存在性。
- 无 `file.download` 返回 403。
- 跨项目文件、回收站文件、版本不属于文件返回 404。
- 同一文件的变更前 / 变更后版本可同时入包。
- 同一版本重复选择只入包一次。
- `entryName` 含 `/`、`\`、`..`、控制字符、首尾点或空格时被安全清洗。
- 中文、日文、韩文和 emoji 文件名不乱码。
- 同名文件追加 `_2`、`_3` 且保留扩展名。
- 已压缩格式使用存储模式，普通文本 / Office 文件按策略压缩。
- 单文件超过 200 MB 整批失败；总量超过 2 GB 整批失败。
- 对象存储读取失败、ZIP 写包失败、上传失败均不返回缺件包。
- 生成超时和请求断开后临时目录被清理。
- ZIP 生成成功后才返回签名地址，地址过期后不可继续下载。
- 临时对象在 TTL 后被清理任务删除。
- ZIP 审计条数与约定一致，metadata 含 `batchId` 和 `versionId`。

### 9.2 ZIP 完整性

- `unzip -t` 或等价工具检查无损坏。
- 对比每个条目的文件名、大小、SHA-256 和源版本对象。
- 检查条目顺序与用户选择顺序一致。
- 检查变更前 / 变更后名称和扩展名。
- 检查没有临时路径、对象键或服务器绝对路径进入 ZIP。

### 9.3 前端

- 当前页全选、半选态、清空和跨页保留正确。
- 无版本行不可选。
- 筛选变化清空选择；实时刷新剔除失效行。
- 选择超过 50 项时按钮禁用或提示。
- 分别下载严格串行，进度可见，失败项不阻断后续项。
- 分别下载结束后 ZIP 兜底提示始终可见。
- ZIP 请求期间按钮不可重复点击。
- ZIP 成功后只触发一次下载。
- ZIP 失败后可以重试，也可以退回分别下载。
- 移动端筛选栏批量操作组、复选框和进度遮罩可用。
- 四套语言无缺失 key、无错位。

### 9.4 浏览器实测

- Edge 正式站点：2、11、30、50 个文件分别下载。
- 多文件下载权限保持默认询问，验证拒绝授权时用户仍能使用 ZIP。
- ZIP 与分别下载连续操作时页面状态不串线。
- 浏览器控制台无新增 error / warning。

## 10. 风险与后续

| 风险 | 处理 |
|---|---|
| 浏览器多下载授权无法被页面检测 | ZIP 入口常驻；文案使用“已发起”，不承诺检测拦截 |
| 大量文件导致标签页 / 下载管理器卡顿 | 串行 150 ms、单批 50 个、显示进度 |
| 2 GB ZIP 生成超过网关 300 秒 | 先按 4 分钟超时实现；真实数据持续接近上限时改为异步任务并修订本文件 |
| 临时对象未及时清理 | 一次性清理任务兜底；任务失败需告警并保留可重试语义 |
| 前后端同时修改导致契约漂移 | 先合契约，再分别实现；以生成物检查作为门禁 |
| 同一文件不同版本重名 | 服务端按侧别名称 + 去重后缀处理，并纳入测试 |
| 审计量过大 | 当前逐文件审计并通过 `batchId` 串联；若 C7 可读性受影响，由 wmj 决定批次汇总口径并修订本文件 |
| 真实浏览器与边界尚未验收 | 正式站 2 / 11 / 30 / 50 项分别下载、浏览器拒绝授权、ZIP 下载及 200 MB / 2 GB 边界仍需 px / lan 在真实环境补验 |
| 跨线代改待评审 | 本轮由 lan 按用户授权代做 px 前端与 wmj 契约部分；PR 中必须请求 px、wmj 评审，不得以代改替代负责人确认 |
